- **名称**：模型耐用性优化设计蓝图（harness durability blueprint）
- **编号**：S-006
- **适用场景**：新项目或新平台为 Agent 设计"省 token、快响应、低重复"的提示词与文档组织时；或评估"缓存复用/上下文减开销"类平台理念是否、如何落库时
- **前置输入**：宿主平台能力清单（是否支持提示词缓存/并行调用/代码编排/渐进披露）、当前上下文预算（见 scripts/budget.conf）
- **步骤**：
  1. **效力分层判定**（框架：[AGENT-ADAPTER 第〇节](../docs/AGENT-ADAPTER.md)）：对每条理念先判属"平台 harness 层职责"（规则库无权承载，写了即不可执行空文或漂移条款）还是"可承载层"（提示词/文档/流程资产能落地）。
  2. **四问门槛**（先例：[ADR-021](../docs/adr/ADR-021-universal-hardening-eight-dispositions.md) L47）：①有无实证需求？②成本落在哪？③残留风险能否机械消除？④合法替代是否已存在？——四问全过才有资格进对抗审查。
  3. **同构确认优先于新建**：先映射库内已有机制（下表），已覆盖即零动作——"给已有机制换名字再立项"是负收益。
  4. **落点选择**：生效条款（须重级+对抗审查+ADR）→ 模板/索引（轻级）→ 存档蓝图（零预算，本档）。
- **六条理念×本库映射结论**（2026-11-20 甲乙双路对抗审查实证，行号为本库当时实际位置）：

| 理念 | 判定 | 本库同构机制（行号证据） |
| --- | --- | --- |
| 1 共享提示词缓存（全局/个性化分离） | 平台层职责，不该管 | 通用层"原文照搬一字不改"（AGENTS-GLOBAL L34）已客观产出逐字一致的共享前缀；缓存命中属模型请求层，库内不可观测不可门禁 |
| 2 工具优化少重复读写 | 平台层＋已覆盖 | rules/12 整册即"少重复读"的规则形态（按需加载、禁整库通读）；Read offset/limit 等属宿主工具实现 |
| 3 上下文压缩交接 | 已覆盖且更强 | rules/07＋ADR-013（落点固定、限~30行、随交付同提交、新鲜度机械核对、台账分离）；压缩算法归 harness，规则文本拒绝"压缩着读"（rules/12 L38） |
| 4 能并行不逐个等待 | 已覆盖（审慎约束型） | rules/13 并行认领协议＋分支判定；rules/04 L44 切片验收；S-001 派发模板——本库对并行是约束而非鼓励，"为并行而并行"净增负担 |
| 5 CodeMode 批量编排 | 已覆盖（门禁域）＋待实证（业务域） | 11 项机械门禁＝"中间结果不进上下文"的文档层形态（rules/04 L41）；业务数据批量编排待首个实证场景沉淀 workflow；**直接落库与切片验收正面相撞**（rules/04 L44） |
| 6 工具按需加载（简介先行） | 已覆盖（自实现）＋MCP 协议归平台 | AGENTS.md 路由表＋rules/12 按需读册＋skills INDEX 四栏元数据（ADR-020）＝同一设计模式的自实现且被机械校验；deferred tools 属宿主机制 |

- **触发词**：耐用性、缓存复用、上下文开销、token、按需加载、批量编排、并行优化、提示词缓存、减开销
- **不适用**（本库终局裁定，2026-11-20）：①**生效条款层零吸收**——硬否决清单：不新增任何"平台机制描述"条款；不改 rules/12 预算阈值（budget.conf）；不动 rules/04 切片验收与机械校验条款；不动 AGENTS-GLOBAL 通用层封闭清单。②S-001"并行性"标注栏**待实证**——"两片是否共享口径假设"无法机械判定，形式合规有实质失控灰区；复活条件＝首个"串行等待损失"记账（PITFALLS 或用户痛点实证）。③业务数据批量编排**待实证**——零业务实证前不立通用条款（P-002/P-004"无证据不落实"口径）；复活条件＝首个业务项目出现可测量的上下文浪费，沉淀为 workflow。
- **判定标准（验收）**：使用者能对任一条平台理念独立完成效力分层判定＋四问，产出"落/不落/待实证"三态结论并给行号证据，而非直接照搬理念原文落条款。
- **完成判据**：蓝图被实际消费的证据已落账——待实证项的复活条件被触发并完成裁决（结果记 PITFALLS 或新 ADR），或任一新项目/新平台依本蓝图完成评估并留存三态结论记录。
