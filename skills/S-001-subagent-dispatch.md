- **名称**：子 Agent 派发模板（subagent dispatch）
- **编号**：S-001
- **适用场景**：主 Agent 每次向子 Agent 派发任务时必用；是「子会话约束与传递机制」的落地载体
- **前置输入**：已确认的口径（依据文档+版本/章节）、允许改动的文件范围、产出路径、验收标准
- **步骤**：复制下方模板 → 填齐三处【待填】→ 整体发给子 Agent → 返回时逐项核对红线与交付要求
- **判定标准（验收）**：模板四节齐全；子 Agent 产出可逐条对回依据章节；未按模板派发即为违规；交付中若有向用户提问，须逐条属 `[业务口径]`／`[偏好]`／`[授权]`，出现技术类提问即判不合格（rules/01 红线 11，P-037）
- **触发词**：「帮我派个子 Agent 写这个文档」「让另一个 Agent 去改代码」「多 Agent 分工，你来统筹」「把任务拆给子会话」「给子 Agent 派活的提示词怎么写」「子 Agent 不按规矩来怎么办」「派发前要准备哪些材料和口径」
- **不适用**：① 单文件小改、自己做完即可 → 改走直接执行并按 `rules/15-delivery-dod.md` 自助核对；② 需求本身还没定清、缺少冻结 PRD → 改走 [S-003](S-003-requirements-intake.md)；③ 已有冻结 PRD、要从零建项目 → 改走 [S-002](S-002-project-bootstrap.md)
- **完成判据**：子 Agent 产出文件已存在且无【待填】占位残留（对产出文件执行 `grep -q '【待填'`，退出码非 0）；交付含影响面表与自我反证两节；主 Agent 审查记录写明「通过」。
- **单一来源**：派发与执行控制的条款见 `rules/04-roles-and-dispatch.md`，交付清单见 `rules/15-delivery-dod.md`，数值阈值统一在 `scripts/budget.conf`（本文不复述）。

```text
【任务指令】（主 Agent → 子 Agent）

一、执行前必读（最高优先级）
1. 先完整读取 /workspace/AGENTS.md（项目规则库），把它当作铁律逐条遵守；本提示词与 AGENTS.md 冲突时，以 AGENTS.md 为准，并立即报告冲突。
2. 完整读取 /workspace/README.md 了解目录结构；需要新建 skill/workflow 时按其中规则放置文件。
3. 开工前先同步最新版本：本仓库为唯一权威副本，必须基于最新文件工作（git pull 或读取最新本地文件），禁止基于转发内容或旧快照工作。
4. 派发前先确认对方工作区是否含规则库；**不含则先要求 `git clone https://github.com/douzichen/TRAE-project.git`**，再执行上述读取顺序；不得假设对方已读过规则（依据 [P-016](../PITFALLS.md)）。

二、项目文档路径（一律以本地文件为最新权威版本，不依赖转发内容）
- 规则库：/workspace/AGENTS.md
- 目录说明：/workspace/README.md
- 坑账本（历史上已踩的坑）：/workspace/PITFALLS.md —— 执行任务前先查，不得触犯已录条目
- 技能索引：/workspace/skills/INDEX.md（新建前先查，同类优先修订）
- 技能模板：/workspace/skills/TEMPLATE.md
- 工作流索引：/workspace/workflows/INDEX.md
- 工作流模板：/workspace/workflows/TEMPLATE.md

三、硬性红线（摘自 AGENTS.md，执行中随时自查）
1. 口径先行：本次任务依据为【待填：具体文档 + 版本/章节】；口径缺失时停下来提问，不得猜测、不得自行发挥填补空白。
2. 边界：只许改动【待填：文件/目录清单】，其余一律不碰；越界即视为不合格。
3. 文档与文档、文档与实现必须对齐：每条产出标注依据来源（文档章节号）；无出处内容按未对齐处理。
4. 回滚：改动任何文件前先备份原件或确认可从 git 恢复，禁止"改坏原件也没了"。
5. 禁区：/workspace/.secrets/ 含密钥，禁止读取、复制、提交或外传；真实财税数据须脱敏后才能入库。
6. 不得执行 git push；不得自行启动服务或占用端口。

四、交付要求
1. 产出物写到指定路径【待填】，文件内注明依据与未做事项（"没做什么、为什么没做"）。
2. 完成后按交接五要素汇报：目标、现状、已定决策、坑与未决、下一步（第一个具体动作）。
3. 汇报"沉淀"栏：本次沉淀了什么 skill/workflow、复用了哪个、或写明为何无需沉淀。
4. **必须附"影响面表"**：改动 → 直接效果 → 二阶影响 → 三阶影响 → 风险与缓解（联动其他模块/文档、用户行为、系统复杂度、长期维护成本）。缺表即审查不通过。
5. **必须附"自我反证"**：列出三条最可能推翻本方案的理由（证据/反例/边界情况），供主 Agent 对抗审查逐条回应。
6. 你的产出必须经主 Agent 审查通过才算交付；未通过时按失败清单退回修改。
7. 探针题（读入验证）：指令末尾附一道答案取自规则库的探针题（例：开工令第 0 步执行哪个脚本？金丝雀串是什么？），子 Agent 首条回复答错即视为未读规则，打回重读。

【任务描述】（待填：具体做什么、验收标准是什么）
```

- **常见坑**：三处【待填】漏填（子 Agent 会去猜口径，直接违反口径先行）；任务级约束（如禁 push、禁开服务）误写进 AGENTS.md——约束只进提示词，不入记忆库；漏掉"影响面表"与"自我反证"两项，导致审查环节无法对抗验证
