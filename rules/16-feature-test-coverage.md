# 逐功能点测试覆盖

> 通用条款（ADR-037）：本册取代本地 IRON-0002；本地专属机制仍见 ADR-035。

## 条款

- **触发**：项目需求确认并完成开发实现、进入交付验收前，必须对需求拆解出的每一个功能点编写测试项；未通过自查不得宣告交付。三个节点：需求确认产出功能点清单 → 实现完成逐点配测试项 → 验收前主审逐条核对。
- **数量**：每功能点 3～5 项（含 3 含 5）。<3 不合规；>5 属冗余，先合并同质项压回 ≤5，确有无法合并的独立角度须主审认可并注明理由。
- **角度互异**：操作步骤、输入类别、预期结果三者至少一项实质不同才算新角度；仅换示例数据或换措辞视为同质；判不准按同质处理，举证责任在编写方。
- **双视角强制**：每点必须同时覆盖（a）**人使用视角**——操作习惯、误操作/异常输入、认知偏差与术语误解、角色分工与场景代入；（b）**高频使用视角**——重复操作的状态累积、边界与极限、重复提交/并发、数据量增长、响应时效与反馈。只有一类即不合规；每项须标明所属视角；归属存疑按未覆盖处理。
- **五字段（缺一不可）**：被测功能点｜视角类别（a/b）｜角度因素｜操作或场景描述｜可判定的预期结果（禁止"正常即可""符合预期"）。
- **实跑**：书面设计为最低要求；财税计算、数据写入、对外接口三类关键功能点必须实跑并记录结果与证据；其余可人工走查。
- **功能点粒度**：用户可单独识别、可单独验收的最小操作或产出单元；拿不准按偏细处理。
- **豁免**：错字、单文件小改、措辞修订等轻级任务豁免（按 [06](06-quality.md) 分级）；中、重级一律强制。
- **六条验收判据（任一不符退回）**：①功能点清单完整；②每点 3～5；③双视角齐备；④无同质重复；⑤五字段齐全；⑥无不可验证预期。
- **产物存放**：测试项随项目交付物存放（项目 tests/ 或交付矩阵表）；规则库只存规则正文，不存业务清单。
- **错误示范**：凭印象补清单、只写 1～2 项、同义反复凑数、只走正常路径、预期不可验证、需求变更后清单滞后、把"代码跑通"当覆盖人使用视角。
