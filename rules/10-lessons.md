# 坑账本与避坑机制

> 归属总纲：[AGENTS.md](../AGENTS.md)｜分册编号：10｜本文件为唯一细则来源

- **用户原话（2026-11-18，作为本节的原则触发器）**："在遇到问题后，就要思考：从程序开发者以及这个程序行业中是如何提升这方面能力的？专业的做法是什么？来解决问题"（该原则已提升为全局核心条款，见「执行前必读」，此处保留当时原话作为出处）
- **事实标准（行业的专业做法）**：只把坑"写下来"拦不住重犯；有效的是把每条坑转化成**防复发机制**，优先级：自动检查（脚本/校验/hook）＞ 模板与清单条目 ＞ 规则文本。能自动拦的绝不靠人记。
- **账本落盘**：所有坑统一记入 `PITFALLS.md`，一条一节，格式固定：现象、根因（追问到不能再问）、影响、防复发机制（具体到改了哪个文件/加了哪条检查）、关联章节、状态（已落实/待落实/已升级）。
- **闭环要求**：出坑即记账，记账必须落在防复发机制上才算完成；未落地标"待落实"，且必须进入待确认事项清单推动关闭。
- **传递机制**：每次派发子 Agent 任务时，把与该任务相关的坑条目显式写进任务指令（"此任务历史上踩过 P-xxx，注意……"）；子 Agent 返回后核对是否触犯账本中已录条目。
- **复发即升级**：同一条坑出现第二次，视为防复发机制失效，必须升级（文本→模板→自动检查），并记入该条目的"已升级"状态。
- 与「沉淀的触发点」中的"返工即触发"衔接：返工时先查账本，无对应条目则新建，有则更新。

### 坑条目必填字段（缺项即不合格）

- 每条坑必须含五个字段：**现象**、**根因**（追问到不能再问）、**影响**、**防复发机制**（具体到文件或脚本）、**状态**。
- 缺**根因**或缺**状态**的条目，`scripts/pitfall_check.sh` 会拦截提交；缺**证据/现象**同样会被 `pitfall_check` 阻断。
- 日期、关联等字段可加，但不替代上述五项。

### 新门禁上线流程（2026-11-18，P-015 落地）

- 新门禁（脚本 / hook / CI 检查）必须先以**告警模式**在真实仓库全量跑一次并记录误报；误报未清零前不得接入阻断点。
- 误报清零后才转阻断，并在首次转阻断的提交说明中写明"实跑范围 + 误报数 + 修正内容"。
- 禁止只按想象的格式写正则直接上线；须用真实文件验证，必要时加白名单及表头/占位符过滤。
- **可移植性（P-017，机械拦截优先）**：门禁脚本禁止 `mktemp` 的绝对/盘符路径、`sed -i`、`readlink -f`、绝对路径 `rm`；临时文件一律用仓库内相对路径。由 `scripts/paths_check.sh` 的 [M1-b] 按 `scripts/portable-deny.txt` 拦截，不靠人记。
- **第二平台验证**：转阻断前须在第二个平台（Windows/git-bash 或 macOS）实跑 exit 0，并记录平台、命令、退出码（写进坑账本证据栏或 ADR）；**未做第二平台实跑的只能保持告警模式，不得转阻断**，不接受"脚本头注明仅验证于 Linux"作为豁免。理由与否决项见 [ADR-012](../docs/adr/ADR-012-gate-script-portability.md)。
- 门禁上线后若因误伤导致 `--no-verify` 绕过，按"复发即升级"记入坑账本并修复。
