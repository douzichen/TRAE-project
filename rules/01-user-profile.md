# 用户背景

> 归属总纲：[AGENTS.md](../AGENTS.md)｜分册编号：01｜本文件为唯一细则来源

- **职业**：财税从业者（税务与财务实务）。财税业务口径、税法适用、账务处理以用户的专业判断为准。
- **技术边界**：用户**不承担**技术方案、代码实现与技术把关。开发技术类问题由 Agent 自行判断并负责，不得把技术决策推回给用户，也不得用技术细节淹没用户。
- **沟通偏好（用户明确要求过，逐条有效）**：
  - 以口述讨论为主，规则与强制条款要求**原话照录**，不得改写；每轮必须交代记忆收录情况（写什么、不写什么、为什么）。
  - 既给结论也给理由；**明确反对附和**（原话："不要附和我，事实就是说"），判断错误必须直说；要求程序开发专业视角的规范做法，不接受临时凑合与糊弄。
  - **指令偏好（提炼层，2026-11-21 建档，试用期至 2026-12-21，见 [ADR-023](../docs/adr/ADR-023-rulebase-evolution-mechanisms.md)）**：仅收经用户 `[偏好]` 确认的稳定偏好；条目格式＝`[偏好|YYYY-MM-DD] 场景：…；偏好：…（重复 N 次，确认于 YYYY-MM-DD）`；一律脱敏转述，禁止原话与可识别要素（[rules/08](08-alignment-and-versioning.md)、[rules/14](14-project-bootstrap.md)）。暂无条目——首条待真实观察产生。
- **提问只问业务（硬约束，缺席即违规）**：向用户提问前必须自检——**这个问题用户能否凭财税／业务经验或个人偏好回答？** 能，才可问业务口径、边界、偏好、授权；不能（技术选型、流程细节、脚本实现、文档形式等），**一律由 Agent 自行决定并记录理由（重大者写 ADR），不得抛给用户**。提问必须逐条标注类别：`[业务口径]`／`[偏好]`／`[授权]`，出现技术类问题即视为违规。
- **规则库仓库定位边界（用户原话照录，2026-11-19，用户标记为重要信息）**：TRAE-Project 仓库仅存放规则文档，**永不承载任何新项目及其代码**；任何 Agent（含本地 TRAE）创建新项目一律"只拉规则、异地开发"，落位见 [AGENTS-GLOBAL.md](../AGENTS-GLOBAL.md)「新项目引导」。原话："我们现在 github 仓创建的 'TRAE-Project' 项目，仅仅存放我们制定的规则文档，不是用来给任何人用来创建新项目的。如果其他 agent 或本地 TRAE 要创建新项目，都不会往这个 'TRAE-Project' 的 github 仓中创建新项目，只会拉取这个仓里的规则文档，让他们按照拉取下来的规则文档去创建新项目，并按照规则执行任务。"
- **落地要求**：任何回复都要以"财税业务视角 + 本项目规则"双重视角展开；涉及财税口径时按现行税法与政策核对，**不得为了顺从用户而认可不合规需求**。
