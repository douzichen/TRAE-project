# 待确认事项的汇总

> 归属总纲：[AGENTS.md](../AGENTS.md)｜分册编号：07｜本文件为唯一细则来源

- 主 Agent 在开始任何实质工作之前，必须先汇总一份"待确认 / 待处理事项"清单，并持续维护，而不是散落在对话里。
- 清单至少包含：事项描述、为什么要确认（缺失会导致什么）、当前状态（待确认 / 已确认 / 待处理 / 已完成）、关联的工作任务或文档位置。
- 目的：任何时候都能回溯、一眼看到还悬着哪些事，并快速定位到对应的工作任务。清单发生变化（新增、确认、关闭）时同步更新。
- 用户是最终确认人，但**仅限业务口径、偏好与授权事项**；主 Agent 只能推动与整理，不能替用户默认确认。技术事项（技术选型、实现细节、流程形式）由 Agent 自行决定并记录理由，不属"须用户确认"范围。
- **用户缺席期**：一切需用户确认的事项一律冻结（状态"待确认"），**不设代批**；计划性多日缺席可按 [02](02-intake-and-dod.md)"预先授权例外"在缺席前预先批准明确的常设任务范围。终局裁定与复活条件见 [ADR-021](../docs/adr/ADR-021-universal-hardening-eight-dispositions.md)，设计蓝图存档 [S-005](../skills/S-005-absence-delegation-blueprint.md)（2026-11-20）。

## 交接文档（Handoff）必须写全

- 交接不能靠口口相传、不能留给后续会话自由发挥；必须以**交接快照文档**的形式落到文件里，后续会话按文档执行，而不是凭印象补全。
- **最基本的三个要素，一个都不能少**：**口径**（要做什么、边界在哪、依据是什么）、**路径**（涉及哪些文件/目录/入口，改哪里，产物放在哪）、**验收**（怎么判定做完了、用什么命令或标准验证、什么状态算通过）。
- **推荐按五要素写全**（在上述三要素基础上补齐，宁可多写不可缺项）：
  1. **目标**：一句话说清这份交接要产出的结果。
  2. **现状**：目前已有什么，最新一次已验证的结果是什么，哪些是半成品。
  3. **已定决策**：已经定下的事及理由，特别是被否决/放弃的方案及原因（防止后续重蹈覆辙）。
  4. **坑与未决**：已知阻塞、风险、未验证的假设、还没人回答的问题、待确认事项。
  5. **下一步**：要执行的第一个具体动作（而非一堆可能性），以及启动条件与负责人。
- 写交接时必须写"没做什么"和"为什么没做"，不能只写"已完成"。交接内容与项目文档（PRD、FSFSD 等）的口径必须一致。
- **交接必须包含"沉淀"栏**：本次沉淀了什么（skill / workflow）、复用了哪一个、若无需沉淀则写明理由。

## 交接快照（CURRENT.md）与续窗衔接（2026-11-18，[ADR-013](../docs/adr/ADR-013-handoff-snapshot.md)）

- **落点固定**：`docs/handoff/CURRENT.md` 是唯一"当前交接"，按 [templates/HANDOFF.md](../templates/HANDOFF.md) 填写；**不设 archive 目录，git 历史即归档**。限 ~30 行，只写 git log 与交付报告看不到的内容（在途状态、未提交半成品、下一个动作）；与 D-1~D-7 重复的内容一律不写。
- **触发（主次分明，不得靠用户口头提醒）**：主触发——与交付**同一提交**内更新 CURRENT.md；兜底——每日 00:00 复盘比对 `git log -1 -- docs/handoff/CURRENT.md` 与 HEAD，落后即补记；口述收尾仅在"任务未完成就要关窗"时使用（P-002 教训：靠人记必失效）。
- **续窗衔接**：[02](02-intake-and-dod.md) 的"复述需求"仍是第一动作；读 CURRENT.md 并入复述的边界清单一起报——目标/现状/未决/下一步 + 与文档的差异；冲突时**用户当轮指令 > 交接文档口径**（[13](13-concurrency-and-lifecycle.md) 裁决第 1 位）。
- **新鲜度**：新窗口先执行 `git log -1 --format='%h %s' -- docs/handoff/CURRENT.md`，与快照所记内容核对；不一致即声明「交接可能过期，以 git log 为准」，不得把过期快照当权威（P-018）。
- **待确认台账与快照分离**：本册第一节的待确认清单是常青台账，随状态更新、不随任务归档；CURRENT.md 只放指针。

## 冷启动自检

- 首条回复必须声明规则加载状态：已读 `AGENTS.md`（+本轮相关 rules 分册）／未确认加载。
- 未确认加载时首行写「未确认加载：含规则库」，且不得以"按规则"为名下结论。
- 判断规则未加载时，第一动作是读 `AGENTS.md` 与 `rules/00`、`01`、`02`，再动手。
- **新会话先自检**：第一条命令执行 `sh scripts/session_start_check.sh`（[ADR-014](../docs/adr/ADR-014-session-start-selfcheck.md)）；落后先 pull，退出码 1＝缺文件/金丝雀缺失、2＝版本未核对须在交付声明、3＝本地落后远端须先 git pull --ff-only 再开工（[ADR-019](../docs/adr/ADR-019-startup-sync-gate.md)），不得在旧副本上宣布"文件不存在"（P-018）。
