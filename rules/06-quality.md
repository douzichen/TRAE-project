# 问题与决策质量

> 归属总纲：[AGENTS.md](../AGENTS.md)｜分册编号：06｜本文件为唯一细则来源

### 任务分级触发（先分级，再决定启用哪些条款）

- **轻**：改错字、单文件小改、单个脚本修订、补充条目措辞 → DoD + 影响面（简版）。**单个脚本或单份文档的修订一律属轻**，不得升格套用重级流程。
- **例外（优先于上条）**：修改或新增**规则条款**一律属"重"级——规则影响所有后续会话，不能按"单份文档修订"处理。
- **中**：新增功能或文档、跨 2~3 个文件的协同改动、每日定时复盘 → 加"方案候选与推荐"+"影响面表"。
- **重**：架构调整、**改变既有规则含义**、不可逆操作、跨多模块 → 加"跨领域类比""对抗审查""ADR""零上下文接手测试"。
- 分级错误（该重的按轻做）视为不合格；分类不确定时**按重处理**。
- **定时任务预授权边界**：每日复盘按"中"级执行，只授权"只读分析 + 补记/升级 PITFALLS 与防复发机制文件 + 提交推送"；若判断需要改动规则含义或业务文档，**只提建议、不动手**，留待用户确认。

### 方案候选与推荐（只让用户决策他能判断的事）

- 重大决策必须给 **3 版方案**，并明确标出**推荐项与推荐理由**。
- **边界（防止把技术决策推回用户）**：三版必须落在**用户能判断的维度**上——业务效果、范围、周期、成本、风险偏好；**技术选型、实现细节由 Agent 自行决定并写清理由**，不得让用户选技术。
- 三版必须有实质差异（业务效果/成本/风险各有侧重），不是同一方案的措辞变体；若三版实质上无法给用户带来新的判断依据（用户只能直接采纳推荐项），**说明理由后只给 1 版推荐方案**，不硬凑三版。

### 影响面推演（审查必填产物）

- 任何改动除直接效果外，必须推演**二阶、三阶影响**：其他模块与文档、用户行为、系统复杂度、长期维护成本。
- 交付时必须给出"影响面表"：改动 → 直接效果 → 二阶 → 三阶 → 风险与缓解。**缺此表视为审查不通过。**

### 对抗审查（独立反方，不许自己审自己）

- 审查环节固定一步：由**独立子 Agent** 扮演最强反对者，给出至少 3 条能推翻方案的证据、反例或边界情况；主 Agent 必须逐条回应后才可通过。
- 主 Agent 自己扮演反对者不算完成此步。

### 跨领域类比（有条件启用）

- 仅在项目内无先例的技术选择时启用；必须给出该做法的**成熟度与不适用条件**，不得只讲好处。

### 决策记录（ADR，优先于翻 Git 历史考古）

- 重要决策写入 `docs/adr/`，一条一文件：背景、候选方案、决策与理由、否决项及原因、**什么条件下应推翻**。
- **红线**：坑账本、审查结论、ADR、审计记录属**审计资产，永不算历史包袱**，不得以清理为名删除。

### 零上下文接手测试（每批规则后必跑）

- 每新增一批规则或文档，派一个**无上下文的子 Agent**，只给 AGENTS.md 与 README 完成一个小任务；它卡住的点就是认知成本，必须消除。
- 规则库膨胀同样受此约束：让规则库变难用的新增属负收益，应合并精简而非叠加。

### 阶段复盘与聚类（不只统计，要找共同根因）

- **每日定时复盘（用户要求，2026-11-18）**：每天 **00:00（Asia/Shanghai）** 由定时任务自动执行一次复盘，任务 ID `._LP-ABG40ZAUH`（名称"每日复盘与根因聚类"）。执行内容：统计自上次复盘以来的提交与返工/回滚/中断记录 → 横向聚类找共同根因 → 升级为自动化/模板/规则 → 结论回写 `PITFALLS.md` → 输出简短结论；确实无新问题须写"本日无新增坑"，不得编造。
- **补充触发**：每累计 5 条坑或每个阶段结束，额外做一次聚类，不受每日任务限制。
- 只统计"发生了什么"不合格，必须给出"共同根因 + 已落地的防复发机制"。
- 定时任务不可用（调度器缺失、沙箱重建）时，退化为"每次会话首次交互时检查昨日是否已复盘"，并当场说明，不得静默跳过。
- 原文存档：本组条款来自用户提供的《我用 Agent 干活最爱说的几句 Prompt》十条，原文见 `prompts/QUESTION-BANK.md`。
