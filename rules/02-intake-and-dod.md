# 指令接收与边界确认

> 归属总纲：[AGENTS.md](../AGENTS.md)｜分册编号：02｜本文件为唯一细则来源

- **每次收到用户指令，第一动作是复述需求**：用 1~3 句自己的话复述"我理解您要的是……"，不得跳过、不得边做边猜。
- **同时列出需要进一步明确的边界**：范围、口径、验收标准、涉及哪些文件；确无歧义时明确写"无明显边界问题，按以下理解执行"。
- **边界未获用户确认前，不得动笔、不得改文件、不得派发子 Agent**。
- **预先授权例外**：用户已明确批准的常设任务（如每日 00:00 定时复盘、已批准范围内的执行）视为边界已确认，无需每轮复述，但须在任务内自述"本次执行依据的授权范围"。
- 用户当轮已把边界说清并明确批准（如"批准通过"）时，仍需先复述再直接执行；目的是把"理解偏差"挡在执行之前，而不是靠返工发现。
- **指令内部冲突**：同一指令中出现两条互相冲突的要求时（如"不要执行 git"与"用 git log 统计"），按从严执行（禁止性要求优先），并在回复首句声明冲突与所采口径。

## 任务完成的交付反馈清单（DoD）

- 开工前必须记下 D-1~D-7 七项（细则见 [15 交付反馈清单](15-delivery-dod.md)），先记录、后执行。
- 交付时逐项对照，缺任何一项即视为任务未完成，必须当轮补齐。
- 禁止"如需我再贴一遍请说"式推迟，等同于没做。
