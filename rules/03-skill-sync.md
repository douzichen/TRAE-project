# 技能同步规则

> 归属总纲：[AGENTS.md](../AGENTS.md)｜分册编号：03｜本文件为唯一细则来源

- **用户强制条款（2026-11-18 口述，原话照录）**：
  1. 改任何 Skill 之后必须同步更新已安装副本，不许只改草稿。
  2. 副本必须对齐；同步后必须做核对并报出结果，`.py` 须返回 `Skill is valid!`，且安装副本与镜像的字节数、修改时间须一致。
  3. 忘同步即视为任务未完成；因占用等原因同步不了，必须当场说明，不得默不作声。
- **行业对应**：源与部署副本漂移问题的标准解法——单一事实源 + 发布管线 + 发布后校验和核对 + 禁止静默失败；上述条款与之逐条对应。
- **本项目落地映射**：
  - 源 = `skills/*.md`、`workflows/*.md`（唯一可编辑处）；已安装副本/镜像 = git 仓库副本（远端 + 各子 Agent 环境 pull 所得），一律不许手改副本（本条"镜像"仅指 git 副本，不含「外部只读镜像」节的飞书镜像）。
  - 同步动作 = 提交 + 推送。`md_check.sh` 门禁：skills/workflows 存在未提交散改即拦截——改了不提交 = 未同步 = 任务未完成。
  - **推送一律由主 Agent 执行**；子 Agent 完成修改后把状态改为待审查并回报，由主 Agent 审查通过后推送。
  - 核对报出 = md_check 结果 + 推送后 `ahead 0` 确认；分支领先远端时 md_check 非阻断提醒"未推送 = 同步未完成"。在 git 仓库内以 git 对象哈希保证内容一致（不做重复比对）；**无 git 的环境**（导出副本）必须实际比对字节数与修改时间并报出结果。**验证型外部 Agent 一律只读**：可本地 commit 跑门禁，但不推送、不比对报出，边界见 [04](04-roles-and-dispatch.md)。
  - `.py` 校验器与 `Skill is valid!` 属具备安装制 skill 工具链的环境约定：在那种环境执行时按原条款照办；本仓库以 md_check 为对应物。
  - 同步不了（远端不可达、凭据缺失、占用等）必须当场说明，并在待确认事项清单登记，不得默不作声。

## 外部只读镜像（飞书知识库，2026-11-25，[ADR-033](../docs/adr/ADR-033-precipitation-dispatch-and-mirror.md)）

- 镜像定位＝**用户本人在飞书的阅读版**；仓库仍是唯一权威副本与唯一可编辑处（[ADR-017](../docs/adr/ADR-017-cross-project-operating-model.md)），镜像不承载条款效力、不参与 md_check 等门禁对账。
- 镜像文档首行必须写"源 commit ＋ 生成时间"；发布动作由主会话经用户本人 lark-cli 执行，按 [04](04-roles-and-dispatch.md)「工具与执行路径判定」先填 [TOOL-PATH-CARD](../templates/TOOL-PATH-CARD.md)，写后回读（节点/文件清单/回读输出留痕于坑账本或交接记录）。
- 发布后当天在 [skills/INDEX.md](../skills/INDEX.md)「镜像」列登记（来源 commit）；**外部 Agent 禁止写镜像**；镜像与仓库不一致时以仓库为准，按过期镜像执行出错按 [10](10-lessons.md) 升级。
