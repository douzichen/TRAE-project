# 技能同步规则

> 归属总纲：[AGENTS.md](../AGENTS.md)｜分册编号：03｜本文件为唯一细则来源

- **用户强制条款（2026-11-18 口述，原话照录）**：
  1. 改任何 Skill 之后必须同步更新已安装副本，不许只改草稿。
  2. 副本必须对齐；同步后必须做核对并报出结果，`.py` 须返回 `Skill is valid!`，且安装副本与镜像的字节数、修改时间须一致。
  3. 忘同步即视为任务未完成；因占用等原因同步不了，必须当场说明，不得默不作声。
- **行业对应**：源与部署副本漂移问题的标准解法——单一事实源 + 发布管线 + 发布后校验和核对 + 禁止静默失败；上述条款与之逐条对应。
- **本项目落地映射**：
  - 源 = `skills/*.md`、`workflows/*.md`（唯一可编辑处）；已安装副本/镜像 = git 仓库副本（远端 + 各子 Agent 环境 pull 所得），一律不许手改副本。
  - 同步动作 = 提交 + 推送。`md_check.sh` 门禁：skills/workflows 存在未提交散改即拦截——改了不提交 = 未同步 = 任务未完成。
  - **推送一律由主 Agent 执行**；子 Agent 完成修改后把状态改为待审查并回报，由主 Agent 审查通过后推送。
  - 核对报出 = md_check 结果 + 推送后 `ahead 0` 确认；分支领先远端时 md_check 非阻断提醒"未推送 = 同步未完成"。在 git 仓库内以 git 对象哈希保证内容一致（不做重复比对）；**无 git 的环境**（外部 Agent、导出副本）必须实际比对字节数与修改时间并报出结果。
  - `.py` 校验器与 `Skill is valid!` 属具备安装制 skill 工具链的环境约定：在那种环境执行时按原条款照办；本仓库以 md_check 为对应物。
  - 同步不了（远端不可达、凭据缺失、占用等）必须当场说明，并在待确认事项清单登记，不得默不作声。
