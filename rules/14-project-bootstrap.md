# 项目创建与需求收集

> 归属总纲：[AGENTS.md](../AGENTS.md)｜分册编号：14｜本文件为唯一细则来源

## 适用范围与项目分级
- 本册属**通用层**（划分见 [AGENTS-GLOBAL.md](../AGENTS-GLOBAL.md)）；项目特定值（路径、端口、库名）写进该项目 ADR 与 README，不写进本册。
- **历史示例（2026-11-18 首个项目，仅供参照，非本仓库承载）**：内网服务 + 网页界面；允许真实财税数据进测试环境但必须脱敏；禁止落任何第三方服务；选型与理由见 [ADR-008](../docs/adr/ADR-008-project-bootstrap-and-requirements-intake.md)。其他项目按 A2/A3 自行推导，不得照搬本节技术栈（本仓库只存规则、不当项目宿主，见 [rules/01](01-user-profile.md)）。
- 分级由主 Agent 在动手前判定并写入 ADR，依据"有无 UI、是否常驻、是否多用户"：

| 级别 | 判定依据 | 必跑步骤 |
| --- | --- | --- |
| 脚本工具型 | 无 UI、非常驻、单人执行 | A1、A7、A8；A2~A6 逐项判定 |
| 单机应用型 | 有 UI、不常驻、单机单用户 | A1~A4、A6~A8；A5 有条件可裁 |
| 内网服务型 | 常驻服务、多用户、内网网页访问 | A1~A8 全跑 |

- **裁剪权**：**A7、A8 不可裁**。裁其余任一步，须由**非起草者的独立审查者**在 ADR 签字，写明理由、风险、补偿动作；缺签字即不得放行。裁 A5 时必须同步改写 A7 的判定口径（"干净环境照 README 跑通"改为 ADR 写明的等效判据），未改写则 A5 不得裁。

## 内网与数据红线（任何级别不得裁）
1. **不引入向外的遥测/上报**：默认上报且无法完全关闭者不选；可关闭者把关闭项写进 `.env.example` 与 README，做不到即换选型。
2. **外部依赖必须可离线安装**：须在无外网环境（内网镜像或 `--no-index`）完成安装并留存命令与输出，否则不引入。
3. **测试数据一律脱敏，脱敏脚本入库**：判定类别、固定占位符与判定三问以 [rules/08](08-alignment-and-versioning.md)「脱敏判定标准」为准；无脱敏脚本即视为未脱敏。
4. **禁止第三方服务调用**：含外部 SaaS、云 API、遥测上报、外部 LLM 回传业务数据；例外须 ADR + 用户明确批准，缺一即禁止。

## A. 需求收集（R1~R6）
- **R1 边界五问**：谁用、解决什么、数据从哪来、合规红线、明确不做。五栏有空缺不进入 R2；技术问题自己定（[01](01-user-profile.md)）。
- **R2 卡片化**：一需求一卡，编号 `RQ-001` 起递增，按 [templates/RQ-CARD.md](../templates/RQ-CARD.md) 填；每个必答项须标出处与状态（用户已确认／待确认／Agent 假设），**无出处即视为未确认，不得写入 PRD**；缺验收标准或缺例外处理的卡，主 Agent 打回。
- **R3 口径确认与到期出口**：财税条目写政策名称 + 条款 + 核实状态，依据 [05](05-requirement-review.md)。待确认项必须登记到期日；到期仍无法核实的二选一——**移出本期**，或**用户书面确认承接风险后带"未核实"标记开发**；禁止静默带病推进。
- **R4 派单与 PRD 审查**：派发、口径先行与"子写主审"按 [04](04-roles-and-dispatch.md) 执行，模板用 [S-001](../skills/S-001-subagent-dispatch.md)；本册只加判定：引用矩阵双向无断链（每张 RQ 有条款、每条条款有 RQ），断链退回原子 Agent。
- **R5 用户确认范围**：只确认业务口径与优先级，技术项不得上单（[01](01-user-profile.md)）；确认人判定为业务项，技术项擅自上单即违规。
- **R6 冻结与变更**：冻结打 tag 与版本纪律按 [08](08-alignment-and-versioning.md) 执行。用户当轮明确指令优先（[13](13-concurrency-and-lifecycle.md) 裁决第 1 位），但**当轮之后必须以变更单补登记**（新 RQ 编号、影响面、受影响条款），未补登记视为未发生。

## B. 项目创建（A1~A8）
- **A1 可执行化检查**：逐卡核对验收标准是否有操作、预期结果、失败条件；只写"良好""正常"或缺失的，打回 R2。
- **A2 初始化决策**：ADR 四栏（约束／选型／否决项及原因／可推翻条件）的写法与分级按 [06](06-quality.md) 执行；本册只加判定：缺任一栏不进入 A3。
- **A3 选型追约束**：选型记录按 [06](06-quality.md) 的 ADR 规则执行；本册只加判定——每个选型须指向至少一条约束原文与出处，指向不了即删除并退回 A2。
- **A4 目录契约**：每目录一句职责，禁止 `misc/`、`utils/`、`其他/` 类无边界目录；骨架至少覆盖迁移、测试、配置、脚本。
- **A5 环境可复现**：解释器与依赖版本锁定、`.env.example`、README 含"5 分钟上手"；新机器照 README 可跑通，缺 lock 或 `.env.example` 即未完成。
- **A6 依赖与许可证**：最小依赖（每个写用途，无用途即删）、版本锁定、禁用 GPL/AGPL 类传染性许可；不满足即换库，例外须进 A2 的 ADR。
- **A7 工具链与门禁（不可裁）**：格式化、lint、测试、pre-commit、CI 全自动，失败阻断；干净环境一条命令跑完且可复现失败。
- **A8 Walking Skeleton（不可裁）**：一条命令跑通"页面 → 后端 → 数据库 → 回显"；不通过退回 A4 或 A3，"能启动"不算通过。
