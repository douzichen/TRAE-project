# 并发认领与生命周期

> 归属总纲：[AGENTS.md](../AGENTS.md)｜分册编号：13｜本文件为唯一细则来源

## 并行认领（多 Agent 同时作业）

- **先登记后动手**：多个 Agent 同时作业时，改任何文件前必须在 `docs/CLAIMS.md` 登记"文件/目录 + 认领人 + 时间"；该文件不存在时先创建，表头固定为 `目标 | 认领人 | 认领时间 | 状态`。
- **同一文件不得两人同时认领**：认领前先查表，目标已被占用即不得开工；认领整个目录视同其下所有文件均被认领。
- **完成后注销**：改完并自检通过后，把自己的登记行状态改为"已完成"并释放；未注销视为仍占用。
- **冲突即停**：发现同一目标存在两个认领人或并发改动，后到者立即停止，不覆盖、不合并，在回复中报告冲突目标与双方认领记录，交由主 Agent 裁决。

## 裁决优先级（结论互相矛盾时）

- 依次比对：**显式规则 > ADR > 当前任务口径 > 默认惯例**；上位存在即按下位，不得越级各取所需。
- 同一层级内，后发布的文件优先于先发布的文件；日期相同时以仓库当前版本为准，不以转发快照为准。
- 仍无法裁决时**停止改动**，在回复中以 `[业务口径]` 标注向用户提问，并写明冲突双方原文、出处与各自影响；不得自行选一个继续。
- 裁决结果必须留痕：写入待确认事项或 ADR，并在相关文档补反向链接。

## 功能退役／需求下线

按以下顺序执行，缺一步即未完成：

1. **标记 DEPRECATED**：在文档标题下加 `> **DEPRECATED（YYYY-MM-DD）**：<替代方案或"无">`；代码与配置保留可识别的注释，不直接删除。
2. **说明为何下线**：写清触发原因、影响范围、替代方案与迁移期限。
3. **保留审计资产**：坑账本、ADR、审查结论、交接记录一律不删，只允许把状态改为"已下线"。
4. **更新索引与反向链接**：同步 README、INDEX、BACKLINKS、路由表及 skills/workflows 中的引用，清除指向已下线内容的有效入口。
5. **提交时说明影响面**：在提交信息与交付回复中列出受影响文件、调用方、定时任务与回滚方式。
6. 禁止以"清理"为名删除文档或审计资产；确需物理删除时，先按 [11 回滚机制](11-rollback.md) 留档，并由用户批准。
