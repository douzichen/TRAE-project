# 并发认领与生命周期

> 归属总纲：[AGENTS.md](../AGENTS.md)｜分册编号：13｜本文件为唯一细则来源

## 适用范围与边界

- **"多 Agent 同时作业"的判定**：同一仓库内 ≥2 个 Agent（主/子会话、跨机器、定时任务）在同一时段对**同一文件或同一目录**有写动作；只读不写不触发。判定人：主 Agent；依据：派发指令中写死的写入范围（[04](04-roles-and-dispatch.md)"只许改哪些文件/目录"）；指令未写范围即退回重派，不得开工。
- **顺序**：02 复述 → 用户确认边界 → 本册认领 → 改文件。认领只是登记台账，不属于 02 的"动笔/改文件"，因此必须排在边界确认之后。
- **权限边界**：本册只定义**分工与生命周期**（谁在做、做到哪、何时退役），**不授权**自行填补文档空白，也不授权裁决口径缺失；与 [04](04-roles-and-dispatch.md)"单一依据、口径缺失就停下来问"冲突时，以 04 为准。
- **分级**：认领、更新、注销 CLAIMS.md 属 [06](06-quality.md) 的"轻"级机械动作，不触发对抗审查、不写 ADR。

## 并行认领

- **唯一台账**：[docs/CLAIMS.md](../docs/CLAIMS.md)（入库、全员可读）。表头固定为：

| 认领人 | 文件或目录 | 开始时间 | 预计结束 | 状态 |
| --- | --- | --- | --- | --- |

- **时间**：`YYYY-MM-DD HH:MM`，时区固定 `+08:00`（Asia/Shanghai）；格式不符视为无效认领，任何 Agent 可覆盖。
- **认领人**：`<角色>-<会话标识>`（如 `子-税审-2b91`），同一会话跨轮不变；只写"我""Agent"等泛称视为无效。
- **状态**：仅 `进行中`／`待审查`／`已完成`／`已放弃`；其他取值视为未认领。
- **先查后领**：认领前必须读表；目标已有 `进行中` 行即不得开工，不覆盖、不合并。
- **目录与文件重叠：具体文件优先**。A 认领 `docs/`、B 认领 `docs/x.md` 时，B 对 `docs/x.md` 独占，A 必须把该文件排除在自己的范围外；A 若已改到该文件，按冲突处置。
- **过期与回收**：仅 `进行中` 状态适用过期回收；`待审查` 状态**不适用**（等待主 Agent 审查期间不计过期）。`进行中` 超过"预计结束"**2 小时**仍未更新即视为过期，**由主 Agent 执行回收**（不是任何 Agent）：回收前须在该行内留注原因，状态改为 `已放弃（过期回收：<原因>；主-<会话> <YYYY-MM-DD HH:MM>）`；被回收的认领由主 Agent 重新派发，原认领人**不得自行重领**同一文件。不得删行、不得改他人历史。
- **注销**：完成或放弃时只改状态、**保留整行不删**（审计痕迹，见 [AGENTS](../AGENTS.md) 红线 9）。
- **释放时机**：子 Agent 自检（按 [15](15-delivery-dod.md) D-1~D-7 自查并跑机械门禁）通过**不等于**释放；子 Agent 完成修改后把认领状态改为 `待审查` 并回报，**主 Agent 审查通过**（[04](04-roles-and-dispatch.md)"审查通过后才算真正交付"）并推送后，再把状态改为 `已完成`；未经审查即释放视为抢占。
- **冲突即停**：开工前发现同一具体目标存在两行 `进行中`，或文件内容与认领时基线不一致（依据：`git status` 中非本人改动、diff 与自己的改动不重合），后到者立即停止，不覆盖、不合并，向主 Agent 报告双方认领行原文。
- **跨分支/跨机器**：认领行须**由主 Agent 先行提交并推送**到 `origin/main`、确认他人可见后才可开工；子 Agent 不得自行推送认领行，只写本地不算认领。CLAIMS.md 冲突时以 `origin/main` 版本为准，合并时保留双方行。
- **推送层**：**推送一律由主 Agent 执行**，子 Agent 不推送任何文件（含认领行）；推送仍按 [08](08-alignment-and-versioning.md) 五步。

### 分支与合并

- **是否开分支**：由主 Agent 在派发时判定并写入任务指令，子 Agent 无权自开。满足任一即开：① ≥2 Agent 并行且写入范围落在同一目录；② 任务跨会话或跨天；③ 需独立审查窗口。三条均不满足则按 [08](08-alignment-and-versioning.md) 直推 main。
- **命名与合并**：`agent/<认领人>-<任务短名>`；合并由主 Agent 在审查通过后执行，子 Agent 不得自行合并或 rebase 他人分支；合并冲突涉及他人认领内容时停止，由主 Agent 处置。
- **合并后**：复跑 [08](08-alignment-and-versioning.md) 的提交五步并更新认领行；删分支不删认领行。

**认领冲突处置示例**：10:00 子-A 认领 `docs/`（预计 12:00）；10:10 子-B 认领 `docs/CLAIMS.md`（预计 10:40），B 独占该文件，A 不得再改它。10:20 B 还要改 `docs/x.md`，须先追加 `子-B｜docs/x.md` 行（文件行优先于 A 的目录行）；A 随后发现该行即停止改动、不覆盖，在回复中列出双方行并报主 Agent 裁决。14:30 A 仍 `进行中` 且无更新（已超过预计结束 12:00 两小时），即已过期，由主 Agent 在行内留注原因、改为 `已放弃（过期回收：…）` 后重新派发，原认领人不得自行重领。

## 裁决优先级（结论互相矛盾时）

仅在**结论互相矛盾**时按下列顺序取舍；上位"有规定"不等于下位永不适用，上位未覆盖的具体点仍向下找依据。

1. **用户当轮明确指令**：本次会话中用户显式说出的要求或批准，可引用原话；用户未撤回即最新。
2. **显式规则条款**：`AGENTS.md`、`rules/`、`schedules/` 中能定位到"文件＋章节/条目"的条款，不含 ADR 正文。
3. **ADR**：`docs/adr/` 中状态为"已接受"的决策记录。
4. **当前任务口径**：任务指令或交接文档（[07](07-pending-and-handoff.md) 三要素）写明的口径。
5. **默认惯例**：以上均无规定时的行业与项目既有做法。

- **同层比较**：以入库 commit 时间较晚者为准，判定人为主 Agent，依据 `git log -1 --format=%cI -- <文件>`；commit 时间相同或取不到时不得择一，转入末条。
- **非依据**：聊天转发件、本地副本、离线导出等"转发快照"只作线索；判定人主 Agent，不满足即忽略，以 `origin/main` 内容为准，并在回复中说明差异。
- **业务口径冲突**：一律停止，以 `[业务口径]` 标注向用户提问，写明双方原文、出处与各自影响，不得自行裁决。
- **技术/文档冲突**：由主 Agent 裁决；改变条款含义时按 [06](06-quality.md) 分级属重级，**必须写 ADR**（并做对抗审查），与 06"改变含义必须写 ADR"一致；并在 [07](07-pending-and-handoff.md) 清单留痕。
- **仍无法裁决**：仅指同层依据并存且 commit 时间相同或不可比较——技术类由主 Agent 定案并写 ADR，业务类按上一条问用户；不得"选一个先做"。
- **示例**：[05](05-requirement-review.md) 要求财税判断写出政策条款，而任务口径称"客户已认可"——服从 05（显式规则），并告知客户认可不能替代政策依据。

## 功能退役／需求下线

按以下六步执行，缺一步即未完成；每步的产出深度按 [06](06-quality.md) 分级，不得把轻级任务升格。

1. **标记 DEPRECATED**：文档标题下加 `> **DEPRECATED（YYYY-MM-DD）**：<替代方案或"无">`；代码与配置加 `DEPRECATED(YYYY-MM-DD): <替代方案或"无">` 注释（按各自注释符）。判定人：主 Agent 审查；缺标记或缺日期即退回。
2. **说明原因**：触发原因、影响范围、替代方案、迁移期限（无期限写"无，长期只读保留"）。
3. **保留审计资产**：PITFALLS、ADR、审查结论、交接记录一律不删，只把状态改为"已下线"。
4. **更新索引与引用**：README、AGENTS 索引、路由表、skills/workflows 的引用改为"已下线 → 替代方案"；**保留指向该文档的链接**（其存在即审计痕迹），BACKLINKS 由 `scripts/link_check.sh` 自动生成，**不手工删改**。
5. **提交说明影响面**：按 [08](08-alignment-and-versioning.md) 五步提交，交付按 [15](15-delivery-dod.md) D-2/D-3 列出受影响文件、调用方、定时任务与回滚方式。
6. **禁止删除**：不得以"清理"为名删除文档或审计资产。仅当对象含密钥/真实敏感数据或内容违法，且经**用户批准**（[07](07-pending-and-handoff.md)"用户是最终确认人"）+ 主 Agent 写 ADR、按 [11](11-rollback.md)"改前备回滚"留档，才可物理删除；条件不齐即退回第 1 步。
- 定时任务**不得**执行退役（[06](06-quality.md)"只读分析＋补记＋提交"的预授权边界），只能提出建议交用户确认。

## ADR 合卷（对抗审查修订版，ADR-021）

- ADR 累计达 **50 条**时必须合卷：[INDEX](../docs/adr/INDEX.md) 分"当前卷/历史卷"两段登记；计数与分卷标记由 `scripts/md_check.sh` 机械执行——达 50 条而 INDEX 未含"当前卷"标记即拦截提交，不靠人眼。
- 摘要条目强制含三字段：**状态、取代去向、原文行号**，与原文同一次提交更新，防摘要漂移。
- 凡被任何活文档引用的 ADR 一律视同当前卷**展开细读**，摘要仅作索引；**禁止凭摘要下结论**（与 [12](12-context-budget.md)"禁用摘要代替细则"同口径）。
- 合卷只摘不删原文（审计资产红线不变）；可推翻条件见 [ADR-021](../docs/adr/ADR-021-universal-hardening-eight-dispositions.md)。
