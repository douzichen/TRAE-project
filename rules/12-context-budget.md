# 上下文预算与按需加载

> 归属总纲：[AGENTS.md](../AGENTS.md)｜分册编号：12｜本文件为唯一细则来源

## 问题与判断

- **问题（用户 2026-11-18 指出）**：规则库随项目增长，而任何 Agent 的上下文窗口都有限，**"读不完规则"是迟早必然发生的场景**。读不完本身不可耻，但若不声明、仍按"我记得的规则"办事，规则就会被执行成"选择性遵守"，比没有规则更危险。
- **判断**：规则库的第一性能指标不是"写得多全"，而是**"在预算内能被完整读完"**。写不进去的规则等于不存在。

## 硬指标（机器校验，超限即拦截提交）

由 `scripts/context_budget.sh` 在 pre-commit 校验，阈值如下：

| 对象 | 上限 | 超限处置 |
| --- | --- | --- |
| 最小必读集（AGENTS.md + 00 + 01 + 02） | 150 行 | 必须把细则移出常驻集 |
| 任一 `rules/` 分册 | 120 行 | 必须再拆分 |
| 总纲 AGENTS.md | 100 行 | 必须精简，只留速查与索引 |

## 加载策略（按需加载，禁止整库加载）

1. **常驻**：`AGENTS.md`（总纲）——每次会话必读。
2. **固定**：00 执行前必读、01 用户背景、02 指令接收与交付清单——每次会话必读。
3. **按需**：按总纲路由表，只读与本任务相关的 1~2 册。
4. **禁止**"为了保险把 `rules/` 全读一遍"：那是预算浪费，会挤掉真正用于干活的上下文，反而降低质量。

## 读取完整性声明（本册最关键的一条）

- 任何 Agent 若**未能完整读取**必需文件（被截断、超出窗口、跳读、只读了摘要），**必须在回复第一行声明**：`未完整读取：<文件清单>`，并说明因此受限的判断范围。
- **禁止**：默认自己已读全；引用没读过的条款；用摘要代替细则下结论。
- 交付时须写明"已加载分册：00/01/02/xx"，让审查方能核对它到底读了什么。

## 超限处置与失败模式防线

- 触达阈值时：**拆分或摘要化**（细则移出常驻集，总纲只留一句结论 + 链接），不得"压缩着读"硬撑；拆分后必须重跑零上下文接手测试。
- 失败模式 ①：摘要冒充细则 → 以分册为准，并即时修正摘要。
- 失败模式 ②：读一半就下结论 → 完整性声明 + 引用矩阵留痕。
- 失败模式 ③：规则继续膨胀 → 本册硬指标在提交时拦截，不靠自觉。
- 外部 Agent（上下文更小者）：按上述顺序加载，并标注"已加载分册"，不得声称读过未加载的内容。
