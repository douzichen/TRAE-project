# ADR-004：为规则库设置上下文预算与按需加载

- 日期：2026-11-18
- 状态：已接受
- 触发：用户指出"开发过程中必然会遇到文件过载、Agent 无法完整读完规则的情况"，要求补充规则，避免发生此类问题。

## 背景

规则库在一天内从 1 份 AGENTS.md（约 240 行）增长为"总纲 + 12 分册 + 多份配套文档"。任何 Agent 的上下文窗口有限：规则越多，越可能出现"只读了一部分却照样办事"，从而把铁律执行成"选择性遵守"。这比没有规则更危险——它让错误带上合规的外观。

## 候选方案

| 方案 | 做法 | 评价 |
| --- | --- | --- |
| A 不设限，靠 Agent 自觉读全 | 无硬指标 | **否决**：不可验证，注定随规模失效 |
| B 全部规则合并成一份超长文件 | 单一文件 | **否决**：越长越读不完，且无法按需加载 |
| C 总纲常驻 + 分册按需 + 机器校验预算 + 未读完必须声明（**采纳**） | 最小必读集 ≤150 行、分册 ≤120 行、总纲 ≤100 行，由 `context_budget.sh` 在 pre-commit 校验；未完整读取须在回复首行声明 | 预算可测量、越界可拦截、读取状态可核对；代价是规则需持续维护拆分粒度 |

## 决策

采纳方案 C，落地为 `rules/12-context-budget.md` 与 `scripts/context_budget.sh`，并挂 pre-commit。

## 否决项与原因

- **否决"给所有 Agent 全文"**：与预算目标直接冲突，且外部 Agent 上下文更小，越给越容易截断。
- **否决"只保留摘要"**：摘要会与细则漂移，且摘要无法作为审查依据（违反对齐红线）。

## 什么条件下应推翻本决策

1. 出现支持"长上下文无损读取"的通用能力，且能证明读全率 100%——此时可放宽行数阈值；
2. 预算阈值导致规则被迫过度碎片化，出现"为拆而拆"、接手成本反升——此时应放宽单册上限，改为按主题合并。
