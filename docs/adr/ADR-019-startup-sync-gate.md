# ADR-019：开工强制握手——本地落后远端即先拉再开工

- **日期**：2026-11-19
- **状态**：已接受（2026-11-19 用户批准，原话"落"）
- **关联**：[ADR-017](ADR-017-cross-project-operating-model.md)（跨项目运行模型与拉取式迭代）、[ADR-018](ADR-018-clean-copy-repull.md)（干净副本重拉机制）、[rules/04](../../rules/04-roles-and-dispatch.md)（条款正文唯一来源，「拉取式迭代」条）、[scripts/session_start_check.sh](../../scripts/session_start_check.sh)（开工自检与 exit 3 四态）
- 本决策把 ADR-014 的自检退出码语义由三态扩为四态（新增 3）；ADR-014 属审计资产保留原文，现行口径以本 ADR 与 [rules/02](../../rules/02-intake-and-dod.md) 为准。

## 背景

规则库同步原靠用户下发提示词驱动：规则库更新后由用户向各 Agent 下发"重新拉取"指令。该机制的缺陷是同步动作依赖人的记忆——漏发即按旧规则开发，且双方无感（执行方不知规则已更新，派发方不知对方在用旧版），与 P-019"布置≠完成"同型（指令发出去不等于动作真的发生）。

另一侧，开工自检脚本（[ADR-014](ADR-014-session-start-selfcheck.md)）自上线起就已在版本核对时输出落后数（"副本落后，先执行 git pull --ff-only origin main 再读规则"），但仅作提示、计入"需处理"态（exit 1），不构成开工门槛——执行者看到提示仍可继续开工，脚本拦不住。

## 决策

条款正文落 [rules/04](../../rules/04-roles-and-dispatch.md)「跨项目运行模型」「拉取式迭代」条，此处概述，共四条：

1. **落后即先拉**：开工自检发现本地落后远端（落后 N>0）时，须先 `git pull --ff-only origin main` 并报新 commit（`git rev-parse --short HEAD`），否则不得开工。
2. **exit 3 四态**：[session_start_check.sh](../../scripts/session_start_check.sh) 新增退出码 3（版本落后）——落后>0 时脚本直接拦截并输出处理指引；原三态 0（可开工）/1（需处理）/2（无法核对远端）语义不变。
3. **锁定版本豁免**：用户显式指令"锁定版本/暂不更新"时，Agent 交付声明"落后 N、按用户指令锁定"即合规豁免——裁决依据为 [rules/13](../../rules/13-concurrency-and-lifecycle.md) 裁决优先级第 1 位"用户当轮明确指令"。
4. **中途同步仍走用户广播**：规则库更新后的中途同步（非开工时点）仍由用户下发"重新拉取"提示词（具体重拉机制见 [ADR-018](ADR-018-clean-copy-repull.md)），本决策不取代该辅助通道。

## 候选方案与否决项

| 方案 | 内容 | 结论 | 理由 |
| --- | --- | --- | --- |
| A（采纳） | 开工强制握手：把同步点对齐开工检查点，自检发现落后即拦截（exit 3），先 pull --ff-only 再开工 | 采纳 | 同步点天然对齐开工检查点（自检脚本本就每次开工必跑）；零平台依赖（纯 git 原生能力）；脚本已具备三态基础，改动最小 |
| B（否决） | 纯提示词驱动：规则库更新后由用户下发"重新拉取"指令 | 否决 | 靠人记忆，漏发即按旧规则开发且双方无感；降为中途同步的辅助手段（决策第 4 条） |
| C（否决） | Webhook 推送：规则库更新时推送通知各外部平台 | 否决 | 豆包/千问/DSH/WorkBuddy 等外部平台无常驻端点，推送无处落地 |
| D（否决） | 平台定时轮询：外部平台定时检查远端更新 | 否决 | 外部平台无调度器可依赖；即便可行，空跑轮询也耗上下文 |

## 适用范围

- **与只读红线的关系**：`git pull` 属读操作（只更新本地副本，不改远端、不上传任何内容），与验证型 Agent 只读红线（[ADR-015](ADR-015-validation-agents-readonly.md)）不冲突。
- **适用对象**：外部验证 Agent 的本地副本，与执行 Agent 项目内的规则库干净副本（[ADR-018](ADR-018-clean-copy-repull.md) 的重拉基线）均适用；两者开工前都须过此握手。

## 什么条件下应推翻本决策

1. 外部平台 pull 通道长期不可用，致开工反复阻塞 → 回退为"落后须声明、不强制拦截"，须另立新 ADR。
2. 实测发现握手频繁打断小任务流（如单会话内小改动被落后拦截反复中断）→ 讨论把握手收窄为仅对"跨会话任务"生效，须另立新 ADR。
