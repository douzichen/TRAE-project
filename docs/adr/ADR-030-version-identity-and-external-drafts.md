# ADR-030：规则库版本标识与外部治理草案处置

- 日期：2026-11-24
- 状态：已接受（主会话依用户 2026-11-24 授权裁决——技术治理自行定夺、一次性汇报不回抛；依据 rules/07「技术事项由 Agent 自行决定并记录理由」与 rules/01 红线 11）
- 关联：[rules/08](../../rules/08-alignment-and-versioning.md)（落点）、[rules/09](../../rules/09-precipitation.md)（沉淀准入）、[rules/06](../../rules/06-quality.md)（重级分级）、[ADR-018](ADR-018-clean-copy-repull.md)（干净副本适用范围）、[ADR-023](ADR-023-rulebase-evolution-mechanisms.md)（外部候选三道闸）

## 背景

2026-11-24 两个外部 Agent（豆包工作、千问助手）执行「重新拉取规则库」后回传六项待确认：① 规则库无版本号，跨项目只能登记 commit；② 项目侧三份治理草案（RULES-CHANGELOG.md、晋升评审流程.md、复盘模板-规则候选栏目.md）抬头称"维护位置：TRAE-project仓"但仓内不存在；③ 是否按 ADR-018 建 `rulebase/` 干净副本；④ 项目 L（外置规则库老项目）路径未明，双向对撞无法启动；⑤ 千问误将规则库本仓当作项目实例做对撞（真源与实例同文件，无分叉可比）；⑥ 是否建 vN.Y 版本登记。均属仓库治理，须主会话裁决。

## 候选方案

| 方案 | 内容 | 结论 | 理由 |
| --- | --- | --- | --- |
| 版本 A（采纳） | commit 号为唯一版本标识，不设 vN.Y、不建 RULES-CHANGELOG | 采纳 | `git ls-remote` 已给可核验哈希；拉取式迭代/ADR-019 握手/豆包实测均以 commit 登记，零新增维护点 |
| 版本 B（否决） | README 登记"规则库版本 vN.N＋对应 commit" | 否决 | 双轨必漂移（改一忘一），无机械校验收益，违反单一来源原则 |
| 版本 C（否决） | 每次推送打 git tag 作规则库版本 | 否决 | tag 与 commit 一一对应时零增量信息；稀疏打点则滞后失真；08 现行 tag 仅用于 PRD 等口径基线 |
| 草案 A（采纳） | 三份草案不入库，项目侧抬头改「草案·待入库」；确需入库走 09→06 重级→ADR | 采纳 | 与既有单一来源重复（见决策 2 理由），入库即造双轨 |
| 草案 B（否决） | 正式入库并登记 v1.0 | 否决 | 绕过晋升闸门（rules/09 沉淀＋rules/06 对抗审查＋ADR-023），且依附被否决的 v1.0 机制 |

## 决策

1. **版本标识＝commit 号（唯一）**：项目侧同步登记 `git rev-parse --short HEAD`，核验用 `git ls-remote origin main`；不设 vN.Y 版本号、不建 RULES-CHANGELOG.md。落点：rules/08「版本管理与历史留存」新增一行；口径 tag（08 原条款）用于口径基线与项目冻结（14 R6），不作规则库版本。
2. **三份项目侧草案在与本仓单一来源等效重复期间不入库**：RULES-CHANGELOG.md、晋升评审流程.md、复盘模板-规则候选栏目.md 与既有单一来源重复——changelog↔git log＋ADR INDEX＋METRICS＋RETRO-LOG 四处台账；晋升流程↔rules/09 沉淀＋rules/06 分级/对抗审查＋ADR-023 三道闸；候选栏目↔rules/09「沉淀触发点」＋rules/10「返工即触发」。由用户/豆包把抬头改为「草案·待入库」；未来确需入库，逐份按 rules/09 触发 → rules/06 重级（对抗审查＋ADR）＋用户批准（ADR-023 三道闸口径）、过 pre-commit 门禁，不打包入库。
3. **ADR-018 适用范围澄清**：`rulebase/` 干净副本仅适用于**项目实例目录**（执行项目）；规则库本仓即条款真源，不存在"副本 vs 实例"分叉，不建副本。已在 ADR-018 尾部加注。
4. **项目 L 对撞挂起**：路径登记 `docs/handoff/CURRENT.md` 待确认（到期 2026-12-01）；拿到路径后再启动双向对撞，未拿到不阻塞任何现行流程。千问的"真源仓无分叉可比"结论成立，其待确认第 3 项按本条答复。

## 否决项及原因

- 版本 B/C：如上表——双轨漂移、零增量信息。
- 草案 B：如上表——绕过晋升闸门、制造重复来源。
- "留待用户裁决"：用户 2026-11-24 明示技术治理自行定夺、一次性汇报，不回抛。

## 什么条件下应推翻本决策

1. 出现 ≥2 个项目消费方要求按语义版本做兼容判定，且 commit 号实测不足以定位 → 重估 vN.N，须另立 ADR。
2. 三份草案对应机制的等效单一来源被实测击穿（发生一次"晋升无据/候选漏登"实际事故）→ 该份草案按 09→06 重级单独入库。
3. 项目 L 对撞发现外置副本与本仓实质冲突且复发 → 升级为规则库治理事项重审。
