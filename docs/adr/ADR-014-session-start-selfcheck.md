# ADR-014：新窗口开工自检脚本与开工令第 0 步

- **日期**：2026-11-18
- **状态**：已接受
- **取代/关联**：[ADR-011](ADR-011-no-auto-injection.md)（无自动注入，靠显式传递）；P-016（规则不自动加载）、P-018（副本落后被当权威，已二次复发）；[ADR-013](ADR-013-handoff-snapshot.md)（交接快照）

## 约束

1. 宿主不自动注入规则（ADR-011 已实证），新会话唯一的入口是用户粘贴的开工令。
2. 多 Agent 并发：TRAE 主/子会话、豆包、千问、DSH、WorkBuddy 各自 clone，副本新旧不一。
3. 跨平台：必须在 Linux 与 Windows/git-bash 都能跑（P-017、ADR-012）。
4. 只读优先：自检不得改动工作区、不得自动合并，避免"自检把仓库改了"的新坑。
5. 不得诱发绕过：脚本不是 hook，不设 `--no-verify` 出口；误报会训练出"忽略红灯"。

## 决策

1. 新增 `scripts/session_start_check.sh`（只读）：输出同源（`AGENTS.md` 与 `rules/00`、`01`、`02` 是否存在）、分支与脏工作区、本地 HEAD、fetch 后的远端 main 与 ahead/behind、`docs/handoff/CURRENT.md` 状态、金丝雀串可见性。
2. 退出码三态：`0` 可开工；`1` 需处理（落后/缺文件/金丝雀缺失）；`2` 无法核对远端（网络或凭据失败）。`2` 与"已是最新"严格区分。
3. `templates/SESSION-START.md` 增第 0 步：先跑脚本并粘贴输出；报"不在 git 仓库内"或脚本不存在时，判定为副本过旧，先 clone/pull 再重来；同时补"记录 commit""复述金丝雀""跨 Agent 声明降级"。
4. `rules/02` 冷启动协议加一行指针（+1 行，必读集 158/160），把自检纳入规则可见范围。
5. README 同步四处：`templates/` 树与描述、`scripts/` 树、`docs/handoff/` 树、`docs/` 职责行。

## 否决项与理由

| 方案 | 否决理由 |
| --- | --- |
| 只在 `rules/02` 加文字，不做脚本 | 属"文本"层，正是 P-018 第一次的做法，已证对"不提交的新窗口"无效 |
| 脚本自动执行 `git pull` | 写操作混入自检；脏工作区或分叉时会把仓库带进不可预知状态，且违背"只读优先" |
| 金丝雀缺失只告警不失败 | 缺失说明副本被改或过旧，属确定性故障；只告警等于默认可开工 |
| 把 `rules/15` 列入启动必读 | 违反 `rules/12`（15 非启动必读），会把必读集推过 160 行 |
| 依赖本地 `origin/main` 引用判断落后 | 无 fetch refspec 的仓库不会更新该引用，会静默报"behind 0"；改用 `FETCH_HEAD` |
| 用 `set -e` | fetch 失败会直接退出，诊断信息打不出来 |

## 对抗审查（2026-11-18，独立子 Agent）

结论"修改后通过"，四条阻塞已吸收：
1. 跨平台：脚本不使用 `mktemp`、绝对路径 `rm`、`sed -i`、`readlink -f`、`[[ ]]`、`timeout`、`stat -c`。
2. "只读"表述改为"只读工作区、不自动合并"，并明示 `git fetch` 会更新 `.git` 内的远端引用；`GIT_TERMINAL_PROMPT=0` 防无 TTY 挂起。
3. 版本核对改用 `FETCH_HEAD`，并区分脏工作区、非 main、ahead>0 分叉。
4. 金丝雀输出注明"仅证明副本内容，不证明宿主已加载"；错误码分三态，避免把"无法验证"说成"最新"。

## 已知局限

- 脚本证明的是"这份副本是什么"，不能证明"宿主加载了规则"；真正的生效仍靠首条回复复述金丝雀与 D-1~D-7 产物（ADR-011）。
- 离线环境只能给出"未核对"，无法替代人工确认。
- 不覆盖"读了但不遵守"，那属于交付审查（rules/06）职责。

## 可推翻条件

1. 宿主开始自动注入 `AGENTS.md`（ADR-011 被推翻）——第 0 步可降为可选。
2. 接入 CI 三平台矩阵并覆盖开工自检——可改为以 CI 结果为权威。
3. 连续 3 次出现"脚本输出与事实不符"且无法修复——回退为模板文本，并按 P-015 重新以告警模式上线。
