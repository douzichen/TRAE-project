# ADR-017：跨项目运行模型——规则唯一通道、写入口唯一、拉取式迭代

- **日期**：2026-11-19
- **状态**：已接受（2026-11-19 用户逐项定调）
- **关联**：[ADR-015](ADR-015-validation-agents-readonly.md)（验证型 Agent 只读）、[ADR-013](ADR-013-handoff-snapshot.md)（续窗衔接）、[rules/01](../../rules/01-user-profile.md)（仓库定位边界）、[rules/04](../../rules/04-roles-and-dispatch.md)（本决策条款正文的唯一来源）

## 背景（用户五问定调，2026-11-19 原话要点照录）

1. **新项目远端仓库**："不用建，让开发项目的人和其他agent自己去创建"；"其他Agent 对该新项目仓库只能获取规则文档，一概不能上传文档（规则库仓库只读不变），如要新增规则，我都会通过你TRAE这唯一的口子来追加或调整规则文档。"
2. **迭代循环**："每个新项目开始就获取拉下github'TRAE-Project'项目仓中的项目规则文档，如果新项目在进行中遇到了各种问题，我们在唯一的规则库通道中新增追加规则或调整规则文档后，再次通过'提示词方式'让其他agnet再次去拉取……并按照更新后的规则文档继续执行项目的开发任务。"
3. **题材**："没有固定的项目题材，通常就是围绕excel、多维表来处理数据分析和应用。把多个步骤的skill收拢汇集成一个workflow的工作流。"
4. **介入原则**："我们不介入任何项目，只会在其他agent执行我们制定的规则中发现有漏洞，我会把问题抛给你……修改已有的规则库文档并上传github'TRAE-Project'项目仓中，然后重新给其他agent指令下载新的规则文档，并按新规则执行。"
5. **终审权**："新项目的这些文档就不归我们管了，都由其他agent新创项目的主agent和子agnet在我们的规则中去执行就好了。"

## 决策

条款正文落 [rules/04](../../rules/04-roles-and-dispatch.md)「跨项目运行模型」五条，此处仅概述：

1. **规则唯一通道**：新项目开工只从本仓库拉取规则；落位＝把规则复制到项目目录，本仓库永不承载新项目及其代码。
2. **写入口唯一**：规则增改只经主会话（本地 TRAE）、按用户批准流程；外部验证 Agent、任何子会话、定时任务会话均不得修改或上传规则文档。
3. **新项目仓库自建自管**：执行 Agent 自建并维护其项目远端，与本仓库完全隔离；任何项目内容不得推入本仓库。
4. **拉取式迭代**：开工拉最新规则并记录 commit；规则库更新后由用户下发"重新拉取"指令，执行 Agent 报 `git rev-parse --short HEAD`，主会话/用户以 `git ls-remote origin main` 核验；未报 commit 的"按新规则执行"视为未验证。
5. **产出终审归属**：项目 PRD/ADR/代码由执行 Agent 自身的主/子体系按本规则库流程终审，不经主会话复检；规则缺口走第 4 条迭代循环回到主会话。

## 候选方案与否决项

| 方案 | 内容 | 结论 | 理由 |
| --- | --- | --- | --- |
| A（采纳） | 镜像落位：规则复制进项目目录＋开工记录 commit | 采纳 | 规则如依赖应锁版本：可复现、可对证、离线自足 |
| B（否决） | 指针文件：项目只存规则库 URL/commit，每次开工现拉 | 否决 | 每次开工依赖网络与规则库可用性；规则库坏改会同时打断所有在建项目，且"按新规则执行"无从对证 |
| C（否决） | submodule/subtree 挂载规则库 | 否决 | 外部 Agent 平台能力各异，复杂度超收益 |

## 对抗审查与采纳情况（2026-11-19）

共 5 条意见：2 条流程性、3 条实质性。

- **流程性 2 条**：本决策属重级（改变条款含义），须 ADR＋D-1~D-7 全量交付——已照办。
- **实质性 3 条，全部采纳**：
  1. "自建自管"须写明与规则库**完全隔离**，防"自建即需向规则库 push"误读——已写入 rules/04 第 3 条。
  2. 报 commit 须定核验命令与主体：执行 Agent 报 `git rev-parse --short HEAD`，主会话/用户以 `git ls-remote origin main` 对照——已写入 rules/04 第 4 条。
  3. 与 AGENTS-GLOBAL「新项目引导」交叉引用，防"落位＝项目入本仓库"误读——已写入 rules/04 第 1 条与 AGENTS-GLOBAL 引导第 2 步。
- 另建议 S-004 同步——已在「可直接粘贴的执行指令」追加第 8 条。

## 歧义裁定

用户原话"对该新项目仓库只能获取规则文档，一概不能上传文档"存在两种读法：(a) 上传红线指向规则库；(b) 不许向任何仓库上传。按同句括注"**规则库仓库只读不变**"收敛为读法 (a)：执行 Agent 自建自管其项目远端属其自身环境行为，不属本库管辖，但同样不得向本仓库上传。

## 什么条件下应推翻本决策

1. 用户明确"新项目仓库也不许 Agent 自建/上传"——改为项目全部留在本地执行，不建远端。
2. 实测发现镜像落位导致多项目长期停在旧 commit、迭代失效——重估指针模式（方案 B）。
3. 主会话写入口成为瓶颈——讨论受控授权写入口，须用户书面批准并另立新 ADR。
