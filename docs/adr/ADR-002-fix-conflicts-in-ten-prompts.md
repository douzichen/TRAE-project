# ADR-002：修正十条提问法落地条款的三处自相矛盾

- **日期**：2026-11-18
- **状态**：已接受
- **触发**：ADR-001 落地后，按 AGENTS.md「对抗审查」由独立子 Agent 扮演反方，提出 3 条反对意见，全部成立。

## 背景

ADR-001 把十条提问法写入规则库后，规则之间存在互斥，若不修正，后续会话会在"照哪条"上卡死或各取所需。

## 反方意见（独立子 Agent，节选）

1. **边界确认 vs 定时复盘**：规定"边界未确认不得动笔"，但 00:00 定时复盘无人确认仍须执行；且复盘回写账本被分级为"重"，要求三版方案+对抗审查+ADR，自动任务无法满足，只能违规或空转。
2. **三版方案 vs 技术决策不推回用户**：一边要求给 3 版方案供用户选择，一边禁止把技术决策推回用户；用户无法分辨技术差异，只能照抄推荐项，多耗一轮且无信息增量；且"不确定按重"使改一个脚本也要三方案。
3. **强制引用税法条款 vs 无依据**：要求不合规必须写出政策条款，但仓库无政策库、无检索链路，模型知识有截止时点，遇新规只能编造或引用旧规；且"业务以用户判断为准"与"合规不由用户裁量"同库互斥，缺少优先级。

## 决策

按三条意见逐条修正（不改变用户原意的方向，只修执行口径）：

1. 「指令接收与边界确认」加**预先授权例外**；「任务分级触发」加**定时任务预授权边界**（复盘按"中"级，只授权只读分析+账本与机制文件+推送，动规则含义只提建议）。
2. 「方案候选与推荐」限定为**用户能判断的业务维度**（效果/范围/周期/成本/风险偏好），技术选型由 Agent 决定；**无法带来新判断依据时允许只给 1 版并说明理由**；「任务分级」明确"单个脚本/单份文档修订一律属轻"。
3. 「需求定义审查」新增**依据与不确定性**（须标来源与确定程度，不确定写"需核实"，禁止编造条款号）与**裁量权与优先级**（不替用户裁定、也不为用户背书；用户坚持则记录"已告知风险、用户决定"后执行）。

## 否决项及原因

- 否决"删除 3 版方案条款"：用户明确要求保留并加推荐项，问题在落地口径而非条款本身。
- 否决"删除税法引用要求"：合规提示是本项目核心价值之一，改为"标来源+允许不确定"，而非取消。
- 否决"定时复盘豁免全部规则"：会形成无约束的自动改动通道，改为限定授权范围。

## 什么条件下应推翻本决策

- 项目建立财税政策库与检索链路后：可恢复"必须引用具体条款"的强要求，取消"需核实"的宽松口径。
- 若定时复盘多次发现需要改规则而只能提建议导致积压：应改为"提建议并生成待确认事项卡片"，由用户在会话内批量确认。
