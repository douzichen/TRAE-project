## 二、关键设计决定

1. **F-1 判定改为定义式，不用代理推断**：落库 = `RETRO-LOG.md` 中存在该日期的 `RETRO <date>` 行。凡落库（含合并补跑）必须追加一行；无记录即缺口。红队实测证明"当日有提交触及 PITFALLS/CURRENT"的代理口径会在本案漏报（11-21 因 ADR-023 提交而误判已落库），故弃用。
2. **告警模式上线**：`retro_pending_check.sh` 与 `scan_candidate_check.sh` 均只告警（exit 0），`--strict` 才阻断；满足 rules/10「未做真实回归与第二平台实跑前不得阻断」。转 strict 的条件见"推翻条件"。
3. **单一口径来源**：复盘/简报/审查报告的数字一律引用 `fact_digest.sh` 输出；未出现在其输出中的数字不得写进报告。
4. **不重复立条**：S-2 相关要求已在 rules/01 L11 存在，仅补执行侧核对（S-001 验收项），不新增同义条款（单一来源）。
5. **如实降级**：S-2（提问）与 G-1（聊天输出行数）无法机械拦截，按 rules/10 降至模板档，在此明示"残余风险＝执行自觉"。**因此本轮不承诺"永不重复"，只承诺"可机械化的已机械化、不可机械化的已降级并留痕"**。

## 三、被否决的替代方案（防止后续重提）

- 把复盘并入调度器自动提交：派发沙箱无凭据、审计写入必须经主会话，**否决**。
- 用"当日有提交且触及 PITFALLS/CURRENT"做代理判定：红队实测在 11-21 漏报、历史日误报，**否决**，改台账制。
- 为九项各建一个独立门禁：违反净零增长，**否决**，合并为三个脚本。
- 对"提问"做正则扫描门禁：误报高、误伤合法授权提问（P-015 教训），**否决**，降为模板。
- 在 rules/15 D-6 重复写"三分类标注"：与 rules/01 L11 重复，**否决**（已回退该改动）。
- 把坑条目加"根因族"枚举：见 [reports/R3](../../reports/R3-pstack-research-2026-11-23.md)，无失效实证且边界不可机械判定，**否决**。

## 五、后果与风险

- 三脚本实测记录：`fact_digest.sh` 正常输出全字段；`retro_pending_check.sh` 台账缺失时逐日列缺口、GNU/非 GNU 双分支；`scan_candidate_check.sh` 四态（齐全／缺字段／零候选／矛盾）均按预期。
- 维护面：`RETRO-LOG.md` 需随每次落库追加，漏记即告警（这正是设计意图）。
- 未触碰常驻集：最小必读集 160/160、总纲 99/100、单册上限 120，均未突破。
- 残余风险：S-2 与 G-1 依赖执行自觉；无提交、无会话的日子任何工具都无法提醒（平台层面限制）。

## 六、推翻条件

- `retro_pending_check.sh` 连续 2 个月零误报，且期间真实捕获过 ≥1 次缺口 → 可升为阻断。
- `scan_candidate_check.sh` 在 2026-12-06 首扫与第二次扫描均零误报 → 转 `--strict`。
- 若台账出现"为消除告警而补记但未真正落库"的情况 → 视为机制失效，退回人工核对并升级为坑条目。
- 若近 30 天告警误报 ≥3 次 → 判定口径退回"仅报告最近落库日期"。
