# ADR-029：层级协作链与角色相对化

- 日期：2026-11-23
- 状态：已接受
- 决策人：用户（批准双层方案）

## 背景

规则库此前把「主 Agent＝项目总管、子 Agent＝撰写者」写成固定身份（rules/04 旧 L6-L7）。实际协作中，执行者接单后在自身任务域内即升为主导者：向下派发子 Agent、审查子 Agent 交付物、向上交付由派发方评审。固定身份表述无法承载该链式结构；且通用规则须同时覆盖「单 Agent 执行一个项目」与「多 Agent 共同参与一个项目」两种形态。

## 决议（双层设计）

1. **通用层（模板）**：rules/04 新增「层级协作链与角色相对化」节，条款用抽象角色表述（派发方/执行方/独立反方/定夺人），不写死平台名。核心：角色相对化、形态判据（默认两层/链式 ≤4 层）、层级边界审查（不自审）、退回链路、独立反方、用户定夺、映射句、不放宽声明。
2. **项目层（实例）**：存量项目（纳税申报）角色实例表如下，登记于项目侧 AGENTS.md 项目特定层；通用分册正文不出现平台名。

| 角色 | 实例 | 职责 | 边界 |
|---|---|---|---|
| 定夺人 | 用户 | 业务口径、接受与否 | 不担技术把关 |
| 主导者① | DSH | 派发＋评审 | 对规则库仍只读（rules/04 验证型只读）；项目域写入按 rules/04「写入权」授权 |
| 执行者/本域主导者② | Qoder | 对①交账；对子 Agent 派发＋审查 | 与 rules/04「产出终审归属」同构 |
| 独立反方 | Codex | 只读对抗审查，按需召唤 | 结论须逐条回应；不设强制关卡（P-026） |

## 与既有条款的衔接

- rules/04「验证型 Agent 只读」：DSH 重定调为其在项目域的职能扩展，只读作用域（规则库与远端）不放宽。
- rules/13 写死「主 Agent」处：按 rules/04 映射句读作该层主导者，不改文。
- rules/04「产出终审归属」（新项目由执行 Agent 自身主/子体系终审）：本 ADR 是其显式化与推广，不重写。
- AGENT-ADAPTER 降级表（无子 Agent 时双会话自审）：单 Agent 模式的兜底，继续有效。

## 可推翻条件

出现下列任一情形应推翻本 ADR：① 链式协作实测中「层级边界审查」无法定位责任层（退回链路失效 ≥2 次）；② ≤4 层硬限被证明阻碍真实项目结构且拆片不可行；③ 实例表登记被反复跳过且造成越界写入事故。推翻时按 [rules/08](../../rules/08-alignment-and-versioning.md) ADR 取代流程四步走。
