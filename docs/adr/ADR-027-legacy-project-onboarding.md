# ADR-027：既有项目接入（老项目）——外置引用、只追加、快照范围与只读档作用域

- **日期**：2026-11-23
- **状态**：已接受（2026-11-23 用户选定"先解锁 Qoder，跑通后一次性落 ADR-027"；三轮实测回执齐全后落库，条款草案经独立子 Agent 对抗审查后定稿）
- **关联**：[rules/14](../../rules/14-project-bootstrap.md)（新增 C 节）、[rules/04](../../rules/04-roles-and-dispatch.md)（只读档）、[ADR-017](ADR-017-cross-project-operating-model.md)、[ADR-018](ADR-018-clean-copy-repull.md)、[ADR-024](ADR-024-external-agent-instruction-observation.md)、[PITFALLS](../../PITFALLS.md) P-038~P-040、[docs/AGENT-ADAPTER.md](../AGENT-ADAPTER.md)

## 范围声明（先读，防误读）

1. 本 ADR **只新增"既有项目接入"路径**，不改新建项目的 A1~A8，不改 [ADR-017](ADR-017-cross-project-operating-model.md) 的规则唯一通道、不改 [ADR-018](ADR-018-clean-copy-repull.md) 的重拉机制。
2. 本文的"项目"指用户既有的、可能自带 `AGENTS.md` 与历史提交的仓库；不是本规则库自身。
3. 本 ADR 属重级（新增规则条款，依据 [rules/06](../../rules/06-quality.md) 重/轻分级），已按重级走对抗审查与 D-1~D-7。

## 背景与证据

- 2026-11-23，Qoder 在另一台设备接入既有项目（下称"项目 L"），共三轮：
  1. 只读核查：项目为 git 仓（工作区 84 项改动：3 修改 + 81 未跟踪）；规则库 clone 位于项目外。
  2. 项目 L 的上级目录建仓：快照 4004 个文件，含约 61M 上游源码；`.gitignore` 排除 `/TRAE-project/`，`git ls-files | grep -c '^TRAE-project/'` = 0。
  3. 项目 `AGENTS.md` 末尾追加 §20（+10 行，32,594→33,986 B，前后哈希已登记于回执，备份 `AGENTS.md.bak-20261123-104842`），未 commit、未 push、未动 84 项改动。
- 实测暴露三处空白：老项目接入无流程（P-038）、规则库副本嵌套的建仓隔离（P-039）、项目 `AGENTS.md` 自称"宿主自动注入"但实测未注入（P-040）。
- 规则库当时全库检索「既有/老项目」零命中，rules/14 仅有新建 A1~A8。

## 决策

1. **判定先行**：接入前跑 `git rev-parse --is-inside-work-tree`。是仓→只读报告分支/HEAD/远端/改动数，不 pull/commit/init；不是仓→不得擅自 init，回滚方案写"逐文件备份副本"。
2. **布局默认外置引用**：规则库留在项目外，项目内不复制规则库文件；只在项目根 `AGENTS.md` **追加**一节"通用工程规则入口"（路径、来源 commit、优先级、三条底线）。仅当项目明确要求自包含时，才用内置副本并按 ADR-018 在片边界重拉。
3. **两份 AGENTS.md 不合并**：项目自写文件与规则库总纲是两个对象，只追加、不改名、不覆盖；优先级＝项目特定条款优先，规则库红线不得违反。
4. **覆盖纪律**：覆盖前备份 `<原名>.bak-YYYYMMDD-HHmmss`；只追加不覆盖；写完回读校验（字节数、首行、SHA-256）并报告 diff，不符即回滚。
5. **提交边界**：落盘后不自行 commit/push/pull，交项目自身对齐与提交流程；用户明确授权才提交，且只暂存授权文件，不得卷入在途改动。
6. **快照范围**：首次建仓或首次快照前先列入库范围（顶层目录＋体积）；嵌套规则库副本必须由 `.gitignore` 排除；快照后复核规则库零改动。
7. **只读档作用域**：验证型只读的适用范围与写入授权按 [rules/04](../../rules/04-roles-and-dispatch.md)「验证型 Agent 只读」执行；本节不另定义（单一来源）。

## 与 ADR-017/018 的关系（按 [rules/08](../../rules/08-alignment-and-versioning.md) 修订流程）

- **新建项目**：[ADR-017](ADR-017-cross-project-operating-model.md) 方案 A（镜像落位，复制规则到项目目录）不变；本 ADR 不触碰新项目路径。
- **既有项目**：本 ADR 新增第三类"外置引用"，仅限**已自带治理文件**的老项目。与 ADR-017 否决的方案 B 逐条区分：
  1. B 是"项目只存 URL、每次开工现拉"→ 网络依赖、规则库坏改打断所有项目；本方案是"本机已有 clone、入口锚定 commit、不现拉"，更新只在片边界由用户决定。
  2. B 的"按新规则执行"无从对证；本方案入口写明来源 commit，开工自检报 commit，可对证。
  3. B 无差别适用于所有新项目；本方案仅限老项目，新项目仍按 ADR-017 复制落位。
- **[ADR-018](ADR-018-clean-copy-repull.md)**：仅当老项目选择"内置副本"时适用；外置引用不在项目内产生副本，故不适用。
- **定性**：本 ADR 判定为"新增类别、不取代 ADR-017"；若复审认为构成部分取代，按 rules/08 在 ADR-017 顶部补"部分被取代（限既有项目接入）"标注。

## 否决项

| 否决项 | 否决理由 | 复活条件 |
| --- | --- | --- |
| 默认内置副本（把规则库复制进项目） | 老项目已有成熟治理文件，内置会引入第二套角色与流程、副本过期、两份 AGENTS.md 认知冲突 | 项目明确要求自包含且接受 ADR-018 重拉成本，逐项目 ADR |
| 把"外置引用"推广到新建项目 | 等于复活 ADR-017 否决的方案 B，其网络依赖、全局坏改、不可对证三条否决理由仍成立 | 新项目另行 ADR ＋ 用户明确批准 |
| 覆盖或整文件替换项目 AGENTS.md | 违反项目"只追加不覆盖"，会丢失项目特定治理 | 不复活 |
| 接入即 `git init` 并提交 | 未经范围确认易卷入上游源码、在途改动与规则库副本 | 用户书面授权且先列范围 |
| 接入即 commit/push | 越过项目自身对齐与提交流程，且可能把 84 项在途改动一并卷走 | 用户明确授权且只暂存授权文件 |
| 直接采信"宿主自动注入"类自称 | P-040 实测不成立；采信会导致后续会话跳过读取 | 平台侧提供可复现注入证据 |

## 可推翻条件

1. 连续两个项目实测"外置引用"导致跨设备不可用或规则版本漂移 → 改为"默认内置副本＋自动重拉"，并重写本节。
2. 只追加方案使项目 `AGENTS.md` 膨胀到无法维护（>50KB 或节数 >30）→ 改为独立入口文件＋主文件单行指针。
3. 任一项目出现规则库副本被提交/推送 → 该项目的接入方案立即停用，按 P-039 复核并重写。
4. "自动注入"类自称在任一平台被证实 → 删除 P-040 的强制显式读取要求，改为平台能力声明。

## 残余风险

1. 外置引用依赖本机规则库路径；换机未同步时入口失效。缓解：入口节写明"以实际 clone 路径为准"，开工自检报 commit。
2. 只读档作用域靠指令声明，无机械拦截；执行 Agent 误写项目外的未授权文件仍可能发生。缓解：交付须声明写入清单，主审按 diff 核对。
3. 首次快照范围靠人确认，无强制清单；大目录仍可能被整体纳入。缓解：先列顶层目录＋体积，异常体积需用户确认。
4. 项目侧"只追加"可能累积冗余；暂无行数门禁。缓解：可推翻条件 2 设阈值。
5. 最小必读集已 160/160 零余量；本 ADR 未增加必读行，但后续任何必读增补须先腾额度。
