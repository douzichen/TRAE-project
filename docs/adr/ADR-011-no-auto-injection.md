# ADR-011：本宿主无自动注入——改为显式传递与可检产物

- 日期：2026-11-18
- 状态：已接受（显式传递路径已获正向验证，见下「正向验证」）
- 性质：机制变更（只改规则的传递方式，不改任何规则条款含义）

## 背景

- 为验证"规则是否被宿主自动加载"，在仓库根 `AGENTS.md` 写入唯一标记 `CANARY-TRAE-7F3A9C`。
- 盲测 3 次全部失败：① 全新子 Agent、禁用一切工具（不读文件）询问标记 → 答"不知道"；② 用户新开主会话、不读任何文件询问标记 → 答"不知道"；③ 新建 `.trae/rules/project.md` 作为入口指针后再测加载顺序 → 仍答"不知道"。
- 结论：本宿主**不存在**任何被自动注入的项目规则位置——已确认无 `.trae/rules`（新建后仍无效）、`.cursor/rules`、`.github/copilot-instructions.md`；`AGENTS.md`、`CLAUDE.md`、`GEMINI.md`、`.cursorrules` 均未被自动加载（实测过程见 [AGENTS-GLOBAL](../../AGENTS-GLOBAL.md)，坑记录见 [P-016](../../PITFALLS.md)）。
- 约束：规则库仍是唯一口径来源，不得为绕开物理限制而删减规则（ADR-007 前提）。

## 候选方案

| 方案 | 内容 | 优点 | 缺点 |
| --- | --- | --- | --- |
| A | 继续寻找可注入位置并依赖自动加载 | 若成功则零操作成本 | 已试 3 个位置全部无效，继续试属于赌运气 |
| B（推荐） | 显式传递＋可检产物：每条新会话/每次派单的首条消息显式给出"读哪些文件"的指令；不听信"我已读"，只认交付产物（D-1~D-7、影响面表、依据核验、引用矩阵） | 不依赖宿主行为，可当场验证 | 每个新会话多一步读取；用户不粘贴开工令时须按"未确认加载"处理 |
| C | 放弃规则库，改为口头约定 | 省去维护成本 | 规则仍是唯一口径来源，失去可审计载体 |

## 决策

- 采纳**方案 B**。因为在本宿主下，**规则的有效性 = 被读取的次数 × 被产物证明的程度**，"写在文件里"不构成生效。
- 落地方式：新会话使用 [templates/SESSION-START.md](../../templates/SESSION-START.md) 的开工令；派单首条消息显式列读取清单；验收只看产物。[rules/04](../../rules/04-roles-and-dispatch.md) 同步写入该要求。

## 正向验证（2026-11-18）

- 另一工作区新开会话、粘贴开工令后，接收方**正确触发"未确认加载"声明**，并拒绝编造 D-1~D-7 内容 → 显式传递路径有效，构成方案 B 的实证。
- 但该会话报告 6 个规则文件均"不存在"，原因是**工作区不同源**：规则库在远端沙箱 `/workspace`（Linux），该会话在 Windows 本地空目录。
- 因此"读不到规则"有两个互不相同的原因，排查顺序为：先确认工作区是否同一份文件系统（是否 clone 了仓库），再怀疑传递机制；**不得把"文件不在本机"误判为"注入失效"**。
- 状态：已接受（显式传递路径已获正向验证）。

## 否决项及原因

- **否决 A（继续寻找可注入位置并依赖自动加载）**：`.trae/rules` 新建后仍无效，子会话与主会话盲测均失败，入口指针引导亦失败；在无新信息前继续尝试属于赌运气，且无法证明"这次会成功"。
- **否决 C（放弃规则库）**：规则仍是唯一口径来源，ADR、审查结论等属审计资产（ADR-006、ADR-010 的前提）；传递方式可以变，载体不能废。

## 影响的已知代价

- 每个新会话多一步读取；开工令需用户或主 Agent 主动粘贴。
- 用户若不粘贴开工令，Agent 必须按"未确认加载"处理，**不得假装读过**，也不得以规则为名下结论。

## 什么条件下应推翻本决策

- 若宿主后续提供自动注入（例如官方项目规则目录被证实会加载），**用金丝雀盲测证明后**，回到自动注入并简化开工令；**不得凭版本更新说明推断已生效**。
- 若显式传递的漏读率长期偏高而盲测仍全失败，回到本 ADR 评估开工令形式，而不是取消验证。
