# ADR-016：口径漂移机械拦截（[M5] stale_terms_check）

- **日期**：2026-11-19
- **状态**：已接受（用户批准）
- **关联**：P-019（复盘聚类第 2 类根因）、[ADR-006](ADR-006-rule-change-two-tier.md)（两级制）、[ADR-009](ADR-009-move-dod-out-of-core.md)（D-1~D-7 沿革）、rules/08（对齐红线）、rules/10（新门禁上线流程）

## 问题

机制演进后，被取代的旧口径字样残留在活文档里，且每次都靠人眼逐处更正：D 项数（D-1~D-6 → D-1~D-7）在 rules/06、rules/13、ROLE-SWITCH-CHECK、ADR-008 四处漂移；金丝雀效力口径在 S-004 四处不一致；门禁档位（"三件套"vs 全链八项）名不副实。2026-11-19 复盘将其定为共性根因，用户批准加机械门禁。

## 决策

1. 新增 `scripts/stale_terms_check.sh`（[M5]，阻断式，挂 pre-commit）：按 `scripts/stale-terms.txt`（数据与代码分离）正则拦截活文档中的旧口径字样。
2. 豁免路径：`docs/adr/`、`PITFALLS.md`、`reports/`——审计资产引用历史原文合法，拦截它们等于篡改审计记录。
3. 违禁清单初始两条：`D-1~D-6`、`D-1～D-6`（全角波浪线）。后续发现新漂移口径即追加一行，属轻级（数据文件，不改代码）。
4. 上线流程按 rules/10：先对真实仓库验证——首轮即抓到 rules/06:9、rules/13:26 两处漏网活规则（更正为 D-1~D-7，属消除矛盾、不改含义的轻级对齐）+ schedules/daily-retro.md 历史说明一处（改写避开字面）；负向探针命中、正向零误报后转阻断。

## 否决项

| 方案 | 否决理由 |
| --- | --- |
| 全库无豁免拦截 | ADR/PITFALLS/reports 记录"当时的事实"是义务不是漂移；无豁免会逼人篡改审计资产 |
| 只改 md_check 加一段 | 检查目标（口径字样）与 md_check 职责（结构完整性）不同源，混入会放大该脚本体积且违禁清单无处安放 |
| 人工清单靠 rules/08 自觉对齐 | P-002/P-018/P-019 三连证明"靠自觉必失效"；本次两处漏网活规则正是人眼清单的证据 |

## 已知局限

- 只拦"已知旧字样"；新口径演进后若忘记把新字样加入清单，门禁不知道。缓解：复盘聚类时把"口径漂移"列为必查项，发现即追加清单行。
- 语义级漂移（表述不同但含义旧）拦不住，仍需对抗审查兜底。

## 可推翻条件

1. 清单膨胀导致误报频发（豁免路径之外合法引用旧口径的场景出现）——改为白名单内联标注（如行尾 `<!-- historic -->`）。
2. 规则库迁移到有语义校验的工具（如 JSON Schema 化的规则文件）——本门禁并入更结构化的校验。
