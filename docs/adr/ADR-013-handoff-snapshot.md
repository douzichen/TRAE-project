# ADR-013：续窗衔接（handoff）机制——CURRENT.md 快照随交付更新、不设归档目录

- 日期：2026-11-18
- 状态：已接受
- 审查记录：经两路独立子 Agent 评审（行业做法对照 + 反方对抗审查），总裁定均为"修改后落地"；本 ADR 即修改后的 v2 方案，评审要点已并入否决项。

## 背景

- 已实证事实：本宿主无自动注入（[ADR-011](ADR-011-no-auto-injection.md)），新会话必须显式读文件；对话中说过但未落盘的内容会丢失（P-003）；本地副本会落后远端并被误当权威（P-018）。
- 现有规则只回答了"写交接"（[rules/07](../../rules/07-pending-and-handoff.md) 五要素），未回答三个问题：交接文件放哪、谁在什么时机写、新窗口读到后做什么动作。审计报告 `reports/C-coverage-audit.md` 已登记缺口③"交接快照固定落盘位置"。
- git log 是逐提交流水、PITFALLS 向后看、ADR 存决策、rules/07 是规范不是实例——**没有任何载体记录"此刻在途状态 + 未提交半成品 + 下一个动作"**。

## 候选方案

| 方案 | 内容 | 优点 | 缺点 |
| --- | --- | --- | --- |
| A（原案，已修改） | CURRENT.md + archive 目录 + 口述"换窗口"为主触发 + 新窗口衔接 | 有落点 | 口述主触发最不可靠（P-002）；archive 撞 rules/13"只增不减"必膨胀；快照易成"第二个过期权威"（P-018 同族） |
| B（推荐） | 交付同一提交内更新 CURRENT.md；不设 archive（git 历史即归档）；限 ~30 行、"存在才读"不入常驻集；衔接时机械比对新鲜度 | 不靠人记；不新增目录噪音；过期可机械判定 | 快照仍是手写物，漏写只能靠复盘兜底 |
| C（否决） | 不落地，只靠 git log + 最新交付的 D-1~D-7 报告接续 | 零成本 | **未提交半成品无处落盘**（P-003 正死在这里）；快照散落各提交消息里，恰好退回已登记缺口 |

## 决策（v2）

1. **落点**：`docs/handoff/CURRENT.md` 为唯一"当前交接"，按 [templates/HANDOFF.md](../../templates/HANDOFF.md) 填写；**不设 archive 目录**，历史用 `git log docs/handoff/CURRENT.md` 查看；限 ~30 行，只写 git log 与交付报告看不到的内容，与 D-1~D-7 重复的内容一律不写。
2. **触发**：主触发——与交付**同一提交**内更新；兜底——每日 00:00 复盘比对 `git log -1 -- docs/handoff/CURRENT.md` 与 HEAD，落后即补记；口述收尾仅在"任务未完成就要关窗"时使用，不得作为主触发。
3. **续窗衔接**：[rules/02](../../rules/02-intake-and-dod.md) 的"复述需求"仍是第一动作；读 CURRENT.md 并入复述的边界清单（目标/现状/未决/下一步 + 与文档差异）；冲突时**用户当轮指令 > 交接文档口径**（[rules/13](../../rules/13-concurrency-and-lifecycle.md) 裁决第 1 位）。
4. **新鲜度**：新窗口先执行 `git log -1 --format='%h %s' -- docs/handoff/CURRENT.md`，与快照所记内容核对；不一致即声明「交接可能过期，以 git log 为准」，不得把过期快照当权威。
5. **预算**：CURRENT.md **不进** [rules/12](../../rules/12-context-budget.md) 的 160 行固定必读集，属"存在才读"的条件文件；[templates/SESSION-START.md](../../templates/SESSION-START.md) 增一条衔接步。
6. **台账分离**：rules/07 的待确认清单是常青台账，随状态更新、不随任务归档；CURRENT.md 只放指针。
7. **机械门禁延后**：新鲜度难以 pre-commit 机械定义（每次提交都触发必误报，P-015/P-017 先例），按"复发即升级"处理；将来升级时检查点放每日复盘而非 pre-commit，且先告警模式实跑（[rules/10](../../rules/10-lessons.md) 上线流程）。

## 否决项及原因

- **否决 A 的 archive 目录**：rules/13 明文"交接记录一律不删"，独立 archive 目录只增不减必膨胀成无人敢动的堆；git 历史本身就是不可变归档。
- **否决 A 的口述主触发**：用户直接关窗口、上下文被自动压缩、会话崩溃三种场景都无法触发写文件；把最不可靠的信号当主触发与 P-002"靠人记必失效"自相矛盾。
- **否决"模板复述 rules/07 五要素全文"**：双源必漂移（P-002 脚本与规则脱节先例）；模板只引用不复制。
- **否决"CURRENT.md 进常驻必读集"**：动态内容会挤爆 160 行预算且难以机械核算；两路审查一致。

## 已知漏洞及缓解

- **漏写快照**：主触发依赖执行者自觉。缓解：每日复盘兜底比对；连续失效则按"复发即升级"转入机械检查。
- **过期快照被误信**：衔接动作强制先做新鲜度比对并声明；比对不过时以 git log 为准。
- **快照与交付报告重复**：模板明令"只写 git log 看不到的内容"，重复即删。

## 什么条件下应推翻本决策

1. **快照连续 3 次被新窗口发现过期且复盘兜底未拦**：转入机械检查（每日复盘输出+告警模式实跑），不直接废止。
2. **连续 3 次仅靠 git log + 最新 D 报告即完成接续**（快照无增量价值）：废止本机制并写替代 ADR。
3. **宿主或工具提供可靠的会话摘要/自动交接产物**：改为自动生成，CURRENT.md 降级为人工补充位。
