# ADR-037：逐功能点测试覆盖升格为通用条款（rules/16），IRON-0002 退役

- 日期：2026-11-27
- 状态：已接受（2026-11-27，用户指令"通用规则和豆包工作都落地"）
- 关联：[ADR-017](ADR-017-cross-project-operating-model.md)、[ADR-035](ADR-035-local-only-rules.md)、[ADR-036](ADR-036-nightly-full-review.md)、[rules/02](../../rules/02-intake-and-dod.md)、[rules/06](../../rules/06-quality.md)、[rules/15](../../rules/15-delivery-dod.md)、[rules/16](../../rules/16-feature-test-coverage.md)、[CONFLICT-MATRIX](../CONFLICT-MATRIX.md)

## 背景

1. "逐功能点测试项 3~5 项、双视角、角度互异"条款最初按用户"不上传 GitHub"的要求，做成只在本机生效的本地规则 IRON-0002（ADR-035 本地专属机制）。
2. 实践发现本地机制的成本高于预期：每台机器都要手工安装（复制正文、回填入口路径与 SHA256），换机、沙箱重建、new clone 后全部丢失；任一环节漏装，规则即静默失效。
3. 豆包等外部工作机器至今未装成 IRON-0002，条款实际只在少数环境生效，与"规则须对所有接入 Agent 一致生效"的目标背离。
4. 用户已明确改为"通用规则和豆包工作都落地"，即通用规则库收录并推送；原"仅本地"口径被推翻。
5. ADR-035 的本地机制本身仍然有效，只是不再用于本条规则；保留给未来确实不能上传的内容，避免把一套仍需要的机制一并废掉。
6. 若继续维持"本地一份、通用一份"的直觉做法，会出现同一规则两份正文、改一处漏一处的双轨漂移，与 ADR-017「规则唯一通道、单一真源」冲突。

## 候选方案

| 方案 | 内容 | 结论 | 理由 |
| --- | --- | --- | --- |
| A（采纳） | 升格为 rules/16 通用条款，同时退役本地副本 | 采纳 | 单一份真源随仓库分发，所有机器与外部 Agent 自动获得；彻底消除漏装 |
| B（否决） | 维持仅本地 IRON-0002 | 否决 | 多机漏装已实证：豆包机至今未装成，换机/重建即丢 |
| C（否决） | 本地与通用双份并存 | 否决 | 双轨必然漂移，违反 ADR-017 单一真源；改一处漏一处 |
| D（否决） | 通用库只放指针、正文仍放本地 | 否决 | 本质等于 B，正文仍靠本机安装，漏装问题原样存在 |
| E（否决） | 加密私有仓 / 私有包分发 | 否决 | 本条款不含客户数据，无加密必要；且引入凭据、分发链与更新同步成本。若未来条款含客户数据，改走 E 或退回 ADR-035 本地 |

## 决策

1. **条款落点**：正文归 [rules/16](../../rules/16-feature-test-coverage.md)（≤120 行），作为唯一细则来源；本地 `IRON-0002-per-feature-test-items.md` 同步停用。
2. **总纲同步**：[AGENTS.md](../../AGENTS.md) 路由行并入既有 DoD 行、分册索引并入 15/16 行、红线速查新增第 12 条；总纲回落至 98/100 行。
3. **分册承接**：[rules/02](../../rules/02-intake-and-dod.md) DoD 条末追加"交付前还须按 16 逐功能点自查"，并新增"边界确认产出功能点清单"，不新增行。
4. **交叉表扩列**：[CONFLICT-MATRIX](../CONFLICT-MATRIX.md) 扩为 00~16（21 行 × 21 列），16×02/16×06/16×15 记 ✓ 并补依据行。
5. **本地副本停用**：三件套移入 `.local-rules/archive/`（只移不删），[.local-rules/L-INDEX.md](../../.local-rules/L-INDEX.md) 的 L-002 状态改为"已升级为 rules/16（停用；文件已移入 .local-rules/archive/）"；`rules/02` 的本地规则条改为"未停用才读"。
6. **机制保留**：ADR-035 的 `.local-rules` 机制与 L 系列编号继续有效，供未来确实不能上传的客户数据类内容使用，不因本条升格而废止。
7. **与其他分册的衔接**：功能点清单承接 [02](../../rules/02-intake-and-dod.md) 的边界确认产物；测试项是 [06](../../rules/06-quality.md) 影响面与对抗审查的输入，任务分级沿用 06；16 是 [15](../../rules/15-delivery-dod.md) D-1~D-7 的前置闸门，未过不进交付。
8. **不存业务清单**：规则库只落规则正文，项目侧测试项随交付物（项目 tests/ 或交付矩阵表）存放，遵守"业务产物不入规则库"的既有边界。

## 已知限制

- 规则库无法机检项目侧 `tests/` 或交付矩阵表的真实内容，"有没有写、写得够不够"仍属文本审查，与 ADR-036「业务产物不机检」同口径。
- "实跑证据"（财税计算、数据写入、对外接口三类的运行记录）依赖项目侧交付核对，规则库只规定要求、不保存证据。
- 外部只读 Agent 可能缺少实跑条件，按自身能力降级并写明降级项，但不得把"未实跑"当合规。
- 停用副本已移入 `.local-rules/archive/` 仅为留档，可能被误认为仍生效；以本 ADR 与 L-INDEX 的状态标注为准。
- 总纲曾打满 100/100，本次已把路由行并入 DoD 行、索引行并入 15 行，回落 98/100；此后新增须先腾挪。

## 否决项及原因

- **B（维持仅本地）**：多机漏装已被实践证实（豆包机未装成），且沙箱重建、换机、new clone 均丢失本地文件；继续只靠本地等于把条款交给运气。
- **C（本地与通用双份并存）**：同一规则两份正文，任何一次修订都可能只改一处，形成漂移；与 ADR-017「规则唯一通道、单一真源」直接冲突。
- **D（通用只放指针、正文在本地）**：指针不解决安装问题，读者仍需本机存在正文；复现 B 的全部缺陷，只是多一层跳转。
- **E（加密私有仓/私有包）**：本条不含客户数据，加密收益为零，却要额外维护凭据与分发链；只有未来条款含客户数据时才转为 E 或退回 ADR-035 本地。

## 什么条件下应推翻本决策

1. 条款若涉及客户真实数据（按 ADR-032 四档去向判定为"不得入库"），必须退回 ADR-035 本地专属，不得留在 rules/16。
2. 若通用库推送导致外部只读 Agent 无法据 16 完成自查（能力或工具缺失且不可降级）→ 改按需分册并给出降级路径，另立 ADR。
3. 若 rules/16 因内容增长超过 120 行或最小必读集逼近 160 行 → 拆册或外移细则，保持预算硬指标。
4. 若 16 在项目侧被普遍绕过（交付未见测试项清单且连续发生）→ 把"测试项清单存在"升级为机械门禁，另立 ADR。
5. 若本地与通用再次出现同一条款两份正文 → 强制回到单一真源，废除多余副本并记入坑账本。
