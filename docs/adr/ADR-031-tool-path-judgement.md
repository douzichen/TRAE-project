# ADR-031：工具调用路径判定——先探能力、再选路径、失败不漂移

- 日期：2026-11-25
- 状态：已接受（主会话依用户 2026-11-25 授权裁决——技术治理自行定夺、一次性汇报不回抛；用户原话：「调用工具总是不稳定，严重的时候会发生漂移，有时候调用工具完全正确」）
- 关联：[rules/04](../../rules/04-roles-and-dispatch.md)（落点）、[rules/06](../../rules/06-quality.md)（重级分级与对抗审查）、[rules/11](../../rules/11-rollback.md)（副作用回滚）、[templates/TOOL-PATH-CARD.md](../../templates/TOOL-PATH-CARD.md)、[skills/S-001](../../skills/S-001-subagent-dispatch.md)、[P-045](../../PITFALLS.md)

## 背景

同一任务在不同会话中工具调用路径不稳定。真实案例（技能包发布到飞书知识库）：会话自带的豆包侧代理身份查知识库被拒（131006 permission_denied、空间列表为空）；正确解法是改用本机 lark-cli 以用户本人 OAuth 身份调官方 OpenAPI（wiki +space-list/+node-list/+node-create、drive +upload --wiki-token、docs +update），全程非网页、非模拟点击，授权走设备码由用户亲手确认，收回用 auth logout。但同类任务中反复出现：身份错配、把权限不足当工具不可用、API 失败即改走浏览器模拟、未查重就重复创建、凭据过期静默失败、无回读即宣称完成。缺的是「工具选择」的判定前置与失败处置通则。

## 决策

1. **落点 rules/04 新增「工具与执行路径判定」节**（7 条）：路径卡先行；通道优先级（官方 API/CLI ＞ SDK ＞ 人工，浏览器模拟为最后手段）；权限不足≠工具不可用；失败不漂移（同一失败两次即停，换道须写失败码/副作用/理由/回滚）；写前幂等盘点；授权由用户亲手确认；动作必回读、失败必上报。
2. **模板**：新增 `templates/TOOL-PATH-CARD.md`（身份与归属、能力探测、通道路由、幂等键、验收回读、回滚与授权六栏 + 失败换道记录），作为"模板级"防复发载体。
3. **派发**：`skills/S-001` 三节新增第 7 条，外部系统动作未填路径卡不得动手（版本升至 v1.4）。
4. **门禁**：`scripts/md_check.sh` 检查 7b 增 `rules/04:执行路径卡`、`rules/04:失败不漂移` 关键词；7c 校验节标题、7 条锚点与 `templates/TOOL-PATH-CARD.md`、本 ADR 均存在，防整节被删除；语义级仍靠文本＋模板，不假装机械覆盖。
5. **坑账本**：新增 P-045，八字段齐全，证据指向本节、模板、门禁与 ADR。
6. **对账**：CONFLICT-MATRIX 04×11 与 11×04 同步翻「✓」、补 04×06/04×11 依据；总纲路由与分册索引就地改写（不增行，总纲仍 ≤100）。

## 否决项及原因

- B/C/D 如上表。
- 「只在 PITFALLS 记一条、不改规则」：坑账本要求防复发机制优先级为自动检查 > 模板 > 文本，仅记账不落条款等于把复发留给记忆。

## 什么条件下应推翻本决策

1. 出现 ≥3 个互不相同的执行环境要求"多通道并行/自动降级"（同一动作须走 API 与浏览器交叉验证）→ 通道优先级改为按环境可配置，另立 ADR。
2. 路径卡实测导致派发成本显著上升且连续 2 次复盘无相关复发 → 降为可选清单，另立 ADR。
3. 出现可稳定判定"是否已填路径卡"的结构化产物（如机器可读任务单）→ 把 md_check 关键词门禁升级为字段级校验。
