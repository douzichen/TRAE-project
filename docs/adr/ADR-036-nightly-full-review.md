# ADR-036：夜间全库审查——每日随 00:00 复盘执行，机械自修、语义只报

- 日期：2026-11-26
- 状态：已接受（2026-11-26，用户要求"任务完成后夜间自动全库审查并纠正"）
- 关联：[schedules/daily-retro.md](../../schedules/daily-retro.md)、[rules/06](../../rules/06-quality.md)、[rules/10](../../rules/10-lessons.md)、[ADR-025](ADR-025-mechanical-root-cause-elimination.md)、[ADR-028](ADR-028-measurement-and-gate-revision.md)、[ADR-034](ADR-034-retro-ledger-enforcement.md)

## 背景

规则库进入每日高频更新期：近三日 ADR-032～ADR-035 连发，规则、脚本、模板、台账同批改动。现有 00:00 复盘只回答"昨天出了什么问题"（返工、回滚、重复修改），查不出另一类系统性失真：

1. **规则库自相矛盾**：两册条款互斥、ADR 结论与现行条款冲突、CONFLICT-MATRIX 的 ✓ 无依据。
2. **声称↔落地失真**：ADR/条款声称"已新增某机制"，脚本或条款实际不存在；台账（RETRO-LOG/METRICS/CURRENT）滞后于事实。
3. **机械性瑕疵累积**：死链、编号断档（ADR/PITFALLS/S/W）、索引漏登、BACKLINKS 过期、术语漂移——其中 PITFALLS 连续性与 S-`*`/W-`*` 登记由 `scripts/md_check.sh` 机械校验，死链/术语/预算有对应脚本，**ADR 编号只以 `docs/adr/INDEX.md` 登记为校验、不存在独立的 ADR 编号连续性脚本**，交叉引用与台账滞后则需人读——这些都要等到下一次改动才被门禁碰到。

但夜间无人值守时自动改语义规则风险高于收益：[rules/06](../../rules/06-quality.md)「定时任务预授权边界」只授权只读分析＋补记机制文件；[rules/01](../../rules/01-user-profile.md) 要求技术决策不推回用户、但**语义规则改动必须用户确认**。故本决策的核心是把"能机器闭环的"与"必须人裁决的"二分。

## 候选方案

| 方案 | 内容 | 结论 | 理由 |
| --- | --- | --- | --- |
| A（采纳） | 并入 00:00 复盘同一次执行；机械类自动修＋语义类只报；报告按需落 `reports/nightly-YYYY-MM-DD.md` | 采纳 | 单一调度、零新增运行时实例；机械/语义二分与 rules/06 预授权边界同构；有修复/有冲突才出报告，避免堆积 |
| B（否决） | 新建独立 23:00 调度任务 | 否决 | 两套调度必然漂移（与 P-019「布置≠完成」同构），且与既有 00:00 复盘重复扫描同一仓库；真源再多一份 |
| C（否决） | 夜间全自动修复，含语义冲突 | 否决 | 无人确认即改条款含义/阈值/优先级，违反 rules/06 预授权边界与 rules/01「语义规则须用户确认」；改错无人拦 |
| D（否决） | 只报告不修复 | 否决 | 死链/登记/编号本可机器闭环，留给人工违反"自动检查优先"的既定原则；报告堆积反而增加人工负担 |

## 决策

1. **沿用 00:00 单一调度**：不新建调度实例，夜间全库审查作为复盘任务的固定子段，写入 [schedules/daily-retro.md](../../schedules/daily-retro.md)「夜间全库审查」节；两者同一次执行，禁止拆成两套调度。
2. **每日范围**：① 近 24h 新增/修改的规则、ADR、脚本、模板（`git log --since` ＋ `git diff`），逐条核对"声称↔落地"；② 全局一致性七查，检查项与真实脚本逐一对应——死链=`scripts/link_check.sh`；编号连续性=PITFALLS 连续性与 S-`*`/W-`*` 登记由 `scripts/md_check.sh` 机检，**ADR 编号以 INDEX 登记为校验，无独立脚本**；交叉引用=`docs/CONFLICT-MATRIX.md` 受影响格是否有依据（人工核对，无专门脚本）；术语漂移=`scripts/stale_terms_check.sh`；预算=`scripts/context_budget.sh`；状态枚举=`scripts/pitfall_check.sh`；台账与事实=`scripts/retro_pending_check.sh`＋`scripts/fact_digest.sh` 核对 RETRO-LOG/METRICS/CURRENT 是否滞后。
3. **机械/语义二分**：可自动修（机械类）——死链修正（仅当目标文件唯一同名可判定时）、INDEX/索引补登、编号断档补齐、BACKLINKS 重生成、明显笔误与格式、预算超限时给出腾挪建议（不自行删改条款）；修完必须复跑门禁并留痕。不得自动修——任何改变条款含义、阈值、优先级、豁免范围的改动；两册条款互相矛盾；ADR 结论与现行条款冲突——只出"冲突清单＋候选处置＋依据（file:line）"，次日由用户裁决，夜间不得自行修改。
4. **报告按需生成（防堆积）**：有自动修复或存在待裁决冲突时才生成 `reports/nightly-YYYY-MM-DD.md`——范围与 commit｜自动修复清单｜待裁决冲突清单｜七查结果｜未闭环项｜与昨日报告的差异；七查全过且无修复、无冲突时不生成报告，只在 RETRO 行写"夜间七查通过、无冲突"。自动修复与待裁决必须分列，禁止混写；应有报告而缺失或六节不全视为当日复盘未完成。报告保留期 30 天，超期由主会话归档或删除（属报告、非审计资产），删除须在当日 RETRO 行注明。
5. **留痕与升级**：RETRO 行摘要须带覆盖锚（沿用 ADR-034）；连续两日同一冲突未裁决，升级为 P 条目候选（rules/10）。
6. **失败不得静默**：任一检查无法执行（环境缺失、脚本报错）必须写明原因，不得判通过。
7. **真源优先，不擅改运行时**：本 ADR 只改仓库真源（schedules）；夜间派发会话不得改运行时实例。
8. **调度器 message 须含本步骤**：schedules L21 的 message 必须包含"夜间全库审查"步骤；更新运行时实例由**主会话**按 P-019 先 GET 核实后执行，真源与实例不一致时以真源为准并在当日修正。本 ADR 落地时不擅改 L21 原文（避免未经核实的运行时改写）。

## 已知限制

- 派发沙箱无推送凭据，夜间报告只在会话内输出，落库（提交＋账本更新）由次日主会话完成；报告缺失时的判定口径与 ADR-025/034 一致：有派发无提交 = 次日补跑。
- 七查全部复用现有脚本，不新增门禁依赖；因此本 ADR 不新增任何阻断项，机械修复的验收＝既有门禁复跑通过。
- 语义冲突的真伪仍属文本审查，机器只能判"是否改动了含义易感字段"（阈值、优先级、豁免范围、must/禁止类措辞），不能判改动是否正确——这正是语义类只报不改的原因。
- 规则无法自动判断"死链修正是否改变引用语义"，故死链自动修限"目标文件唯一同名可判定"；存在同名歧义或目标缺失时只报不改。
- "测试项实跑证据"（真机/第二平台跑通记录）无机械校验，依赖项目侧交付核对，规则库不机检业务产物。

## 否决项及原因

- **B（独立 23:00 调度）**：双调度漂移风险与 P-019 同构，且与 00:00 复盘重复扫描同一仓库，收益仅是"时间更早"，不抵真源分裂成本。
- **C（夜间全自动含语义）**：无人确认即改含义，直接违反 rules/06 预授权边界；一次改错语义规则的代价高于任何机械修复收益。
- **D（只报告不修复）**：机械类问题已具备机器判定与机器修复能力，全留人工违反"自动检查优先于模板、模板优先于文本"的既有优先级。

## 什么条件下应推翻本决策

1. 每日全库扫描使复盘时长超过用户可接受阈值 → 改为"每日增量＋每周全量"，须新 ADR。
2. 机械自修两次改错（改出死链、改错编号）→ 收回自动修复权，全部降为只报。
3. `reports/nightly-*` 在"按需生成"口径下仍持续堆积且无人阅读（报告本身成为负担）→ 收紧为仅在语义冲突时生成，机械修复只写 RETRO 行，须新 ADR。
4. 调度器与真源漂移两次 → 改用代码内定时器或外部编排，须新 ADR 并废止本条。
