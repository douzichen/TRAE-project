# ADR-012：门禁脚本跨平台可移植性——机械拦截不可移植写法，第二平台实跑作为转阻断前置

- 日期：2026-11-18
- 状态：已接受

## 背景

- P-017 事实：本仓库门禁此前只在 Linux 沙箱验证，`scripts/link_check.sh` 用 `mktemp` 产生带盘符的绝对路径并在 `trap` 中 `rm`，WorkBuddy 在 Windows + git-bash（safe-delete 包装）下触发门禁 `exit 1`。门禁本身校验通过，失败发生在清理临时文件时。
- 直接后果：非 Linux 环境下 pre-commit 恒失败，用户只能 `git commit --no-verify`，**全部门禁连带失效**。这与 P-015 同族——门禁误伤会训练出绕过习惯。
- 约束：① 规则必须**机械可执行**，能脚本拦的不得只写进文本；② 不得给"未验证"留下合法出口，否则规则对自己失效；③ 不得因为怕误伤而降低门禁强度。

## 候选方案

| 方案 | 内容 | 优点 | 缺点 |
| --- | --- | --- | --- |
| A | 流程条款：新门禁须在第二平台实跑一次，**或**在脚本头注明"仅验证于 Linux" | 改动最小 | "注明"即合法未验证，且脚本照样阻断，P-017 路径原样复现；记录不落盘、不可核验 |
| B（推荐） | 机械拦截：违禁写法清单 + 门禁脚本自检；第二平台实跑只作为"转阻断"前置，未跑不得转阻断 | 不依赖人记；跨平台零环境依赖；不给自我豁免口子 | 清单是白名单式防御，遇到新写法需补条目 |
| C | 只改 S-004（接入方说明），规则层不动 | 零实施成本 | 接入方看到提示不等于写门禁的人被约束，根因未处理 |

## 决策

- 采纳**方案 B**。
- 违禁写法（门禁脚本与 git hook）：`mktemp` 生成的绝对/盘符路径、`sed -i`、`readlink -f`、绝对路径 `rm`；临时文件一律使用**仓库内相对路径**（如 `.git/xxx.tmp`），`trap` 清理同步用相对路径。
- 拦截方式：`scripts/paths_check.sh` 的 [M1-b] 段读取 `scripts/portable-deny.txt`（固定字符串，一行一条）扫描 `scripts/*.sh` 与 `.githooks/*`，命中即阻断；清单单独成文件，避免门禁脚本自我匹配。
- 第二平台验证保留但**不作豁免**：转阻断前须在第二个平台（Windows/git-bash 或 macOS）实跑 `exit 0`，并记录平台、命令、退出码（坑账本证据栏或本 ADR）；未实跑的只能保持告警模式。
- S-004 只承担"接入方在自己平台上遇到报错怎么处置"的操作提示，不承担"写门禁的人应如何验收"的职责，两者不混写。

## 否决项及原因

- **否决 A（"或脚本头注明仅验证于 Linux"）**：把一个未验证状态写成合规状态，规则对自己失效；且注明后门禁仍是阻断式的，P-017 的故障路径一字未改——受伤的仍是使用者，而不是写门禁的人。
- **否决"只要求记录结果"**：不指定命令、退出码、OS 与存放位置的记录不可复核，等于假安全；改为落进坑账本证据栏或 ADR 的可检索字段。
- **否决"Windows 或 macOS 二选一"作为覆盖面**：平台是开放集合，二选一必漏第三个；按写法拦截才是有限且可穷举的集合。
- **否决 C（只改 S-004）**：S-004 面向接入方，不是门禁作者的验收标准；把作者义务写进读者文档，责任错位。

## 已知漏洞及缓解

- **固定字符串匹配会漏**：如 `rm -f "$tmp"` 中变量为绝对路径时，行内看不到绝对路径字面量。缓解：`mktemp` 已被禁用，绝对路径的主要来源被切断；新发现的写法按"复发即升级"补进 `scripts/portable-deny.txt`，并在 P-017 证据栏记一条实例。
- **注释中的示例会被误判**：脚本注释里出现违禁写法是为了说明原因。缓解：[M1-b] 跳过注释行（行首可含空白后接 `#`）；不得用"整文件豁免"代替。
- **清单本身被删或清空**：删掉清单等于关掉检查。缓解：`scripts/paths_check.sh` 在清单缺失时打印告警；清单属审计资产，按 `rules/06`、`rules/11` 只增不减。

## 实跑证据（告警零误报 + 负向验证）

- 正向：修改 `scripts/paths_check.sh` 自身（去掉其中的 `mktemp`）后，在本仓库全量跑 `[M1-b]`，命中 0 条，`exit 0`；同次 `link_check` 亦 `exit 0`。
- 负向：临时放入含 `mktemp` 的探针脚本，`[M1-b]` 精确报出 `scripts/zz-portability-probe.sh:2`，`exit 1`；探针随即删除。
- 说明：负向验证只在 Linux 完成；按本 ADR 决策，第二平台（Windows/git-bash）实跑仍是 `link_check` 类既有门禁的待补证据，不因本次机械拦截而豁免。

## 什么条件下应推翻本决策

1. **清单误伤正常门禁脚本累计超过 3 次**：回到本 ADR 调整清单条目或匹配方式（如改为语法解析），**不得直接删除检查**。
2. **出现清单漏掉、且已导致某平台门禁失败的写法**：补清单条目并把该实例写入 P-017 证据栏；连续两次同类漏检，须评估改为"门禁脚本统一走同一套相对路径封装"。
3. **CI 提供三平台矩阵（同一提交在 Linux/Windows/macOS 均跑）**：可把"第二平台实跑"降级为"矩阵必过"，机械拦截清单保留为本地兜底。
