# ADR-018：在途项目重拉采用干净副本基线与任务片边界换规

- **日期**：2026-11-19
- **状态**：已接受（2026-11-19 用户批准，原话"落"）
- **关联**：[ADR-017](ADR-017-cross-project-operating-model.md)（跨项目运行模型与拉取式迭代）、[rules/04](../../rules/04-roles-and-dispatch.md)（条款正文唯一来源，「跨项目运行模型」节）、[AGENTS-GLOBAL](../../AGENTS-GLOBAL.md)「新项目引导」（引导第 4 步落副本机制）

## 背景

ADR-017 确立"拉取式迭代"后，重拉动作只停留在提示词级指令（规则库更新后由用户下发"重新拉取"，执行 Agent 报 commit 核验），具体怎么拉、拉完怎么合并，全靠执行 Agent 自觉。实测暴露四类风险：

1. **整目录覆盖冲掉项目特定层**：执行 Agent 把新版规则整目录复制进项目根，按项目改写的"项目特定层"（AGENTS.md 内项目路径、项目化条款等混合体内容）被新版通用层冲掉，项目规则退化为未落位状态。
2. **版本错配**：项目根混合体与新副本目录之间没有对照基线，无法判定哪些段来自哪个版本，差异无从对证。
3. **任务片中途换规致验收基准漂移**：重拉发生在某个任务片执行中途，同一任务片的验收基准前后不一致，产出无法按同一把尺验收。
4. **静默失败**："重新拉取"指令下发后执行 Agent 是否真拉了、拉到哪个 commit，无强制回报点，只凭自述无法核验。

## 决策

条款正文落 [rules/04](../../rules/04-roles-and-dispatch.md)「跨项目运行模型」「拉取式迭代」条，此处仅概述，共三条：

1. **干净副本基线**：项目内保留一份**永不改写**的规则库干净副本（如 `rulebase/` 目录），作为重拉基线；项目根放从副本派生的"项目实例"——副本与实例分离，副本只被 `git pull` 更新，永远不承载项目改写。
2. **分层同步**：在副本内 `git pull --ff-only` 并生成新旧差异清单；`rules/`、`scripts/`、`.githooks/`、`templates/` 等纯通用层目录直接同步新版；项目根的混合体文件（AGENTS.md 等"通用层＋项目特定层"）**禁止整文件覆盖**，须逐段合并、保留项目特定段。与静默失败防线衔接：重拉后首条回复报 `git rev-parse --short HEAD`，主会话/用户以 `git ls-remote origin main` 核验。
3. **任务片边界才换规**：重拉与规则切换只在任务片边界执行，不在任务片中途切换验收基准。

## 候选方案与否决项

| 方案 | 内容 | 结论 | 理由 |
| --- | --- | --- | --- |
| A（采纳） | 干净副本＋派生实例：项目内只读副本作基线，项目根放实例，重拉只动副本与通用层 | 采纳 | 覆盖风险归零（副本永不改写，实例改动可随时与副本 diff）；diff 有据（副本内 pull --ff-only 即得新旧差异清单）；WorkBuddy 实际接入已验证"副本与实例分离"模式可行 |
| B（否决） | 整目录覆盖：把新版规则目录整体复制进项目根 | 否决 | 必冲掉项目根混合体中的项目特定层（风险 1 直接成立）；且覆盖动作发生在项目根，无 diff 基线，冲掉了什么无从对证 |
| C（否决） | git submodule/subtree 挂载规则库 | 否决 | 外部 Agent 平台能力各异（与 ADR-017 否决 submodule 同理），复杂度超收益 |

## 风险与对策映射（四险对应四策）

| 风险 | 对策 | 落点 |
| --- | --- | --- |
| 整目录覆盖冲掉项目特定层 | 副本与实例分离＋混合体逐段合并、禁止整文件覆盖 | 决策第 1、2 条 |
| 版本错配 | 副本内 `git pull --ff-only` 生成新旧差异清单，纯通用层目录以副本为准直接同步 | 决策第 2 条 |
| 任务片中途换规致验收基准漂移 | 任务片边界才换规，不在任务片中途切换验收基准 | 决策第 3 条 |
| 静默失败 | 重拉必报 `git rev-parse --short HEAD`，主会话/用户以 `git ls-remote origin main` 核验 | 决策第 2 条＋rules/04「拉取式迭代」原有条款 |

## 什么条件下应推翻本决策

1. 干净副本与实例分离在多项目实测中维护成本过高（如项目频繁改写通用层、副本与实例 diff 长期无法收敛）→ 重估"整目录覆盖＋强制先 git 提交副本"方案，须另立新 ADR。
2. 任务片粒度过粗导致规则更新长期滞后（片边界迟迟不来、项目长期运行在旧规则上）→ 讨论切片细化或用户例外审批机制，须另立新 ADR。
