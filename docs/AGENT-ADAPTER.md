# 跨 Agent 适配说明（TRAE 以外的 Agent 必读）

> 目的：让豆包、豆包工作、千问助手、DSH、WorkBuddy 等 Agent 读到本仓库规则后**不误解、不误用**。
> 原则：**可以改名、可以降级，不可以改写原意**。

**快速接入请直接用 [`../skills/S-004-rulebase-onboarding.md`](../skills/S-004-rulebase-onboarding.md)（含可粘贴指令）。**

## 二、三步适配（照做即可，不要自行发挥）

### 第 1 步：改角色名（只改名，不改职责）

把规则里的称呼替换为你自己的角色体系，例如：

| 规则中的称呼 | 你可以替换为 | 不可改变的实质 |
| --- | --- | --- |
| 主 Agent | 你自己 / 主控 / 编排者 | 你负责拆解、派发、**逐条审查**，审查通过才算交付 |
| 子 Agent | 子任务、分身、并行会话 | 执行者的产出**必须经审查**，不能自写自过 |
| 用户 | 用户（不要改） | 用户是财税从业者，业务口径以其为准，技术决策**不推回给用户** |

### 第 2 步：改路径与标识

| 规则中的写法 | 在你环境里替换为 |
| --- | --- |
| `/workspace` | 你本地仓库的根目录 |
| `._LP-ABG40ZAUH`（定时任务 ID） | 你自己的调度任务 ID，或按 [schedules/daily-retro.md](../schedules/daily-retro.md) 建立等价任务 |
| `TRAE-project` | 你的项目名 |

### 第 3 步：按能力降级（**降级必须声明，不得假装执行**）

| 本仓库机制 | 若你没有该能力 | 降级做法 |
| --- | --- | --- |
| git hook（`.githooks/`） | 无 hook | 每次会话开始手工跑**完整门禁三件套**：`md_check.sh` + `link_check.sh` + `delivery_report.sh`，提交前另需 `pre-push-check.sh` 等价的凭据检查；缺一不可，并在交付中写明"手工检查" |
| 子 Agent 派发（S-001 模板） | 无子 Agent | 开两个独立会话分别做"撰写"与"反方审查"，并标注"降级：已隔离执行" |
| 单线程 Agent（无法并行派发） | 无第二执行者 | **必须开第二个会话做独立复审，不得自写自审**；复审结论须落文件 |
| 定时调度器 | 无定时能力 | 每日首次会话时执行同一任务内容，标注"降级：会话内触发" |
| bash 脚本 | 无终端 | 逐项手工对照清单，并在交付中列出对照结果 |
| ADR / 分册拆分 | 平台不支持多文件 | 单文件内按同等层级组织，但**不得删减条款** |

> **降级必须量化缺口**：写清缺哪项检查、风险由谁承接；不得把降级当合规。

## 三、四条不可偏离的实质（改名也不许改）

> **重要：以下四条是"最小集"，不是全部红线。**全部红线共 11 条，见 [AGENTS.md](../AGENTS.md) 的"核心红线速查"表；不得只遵守本节而跳过其余条款（尤其是 03 技能同步、08 对齐与版本管理、11 回滚）。

1. **用户是财税从业者**：业务口径以用户为准；技术方案由你负责，不把技术选择推回给用户；不附和，判断有误直接指出。
2. **财税判断必须写出政策名称与具体条款并核实清楚**；核实不到就明确写"尚未核实到对应条款，不作结论"，不得凭记忆编条款号。
3. **收到指令先复述需求并列出待明确边界**，确认后再动手。
4. **审计资产永不删除**：坑账本、审查结论、ADR、交付记录。降级可以，删减不可以。

## 四、交付格式（与 TRAE 版一致）

按 [rules/15-delivery-dod.md](../rules/15-delivery-dod.md) 的 D-1~D-7 汇报：新增段与全文、改动清单、对账结果、收录说明、验证与同步状态、沉淀与待确认。禁止"如需我再贴一遍请说"式推迟。

## 五、发现规则有问题时

- **不要私自改规则**：在你的环境另开分支，提交 PR 说明"哪条与我的平台冲突、建议如何降级"，由本项目维护者审查合并。
- 直接改本地副本会导致本仓库与其他环境分叉（历史坑 P-005）。
